# 집단군 전투 배경·텍스처·효과음 팩 v1

기준: 「사국쟁패 Studio (58).html」, 표시 버전 v0.53.0.

이 팩은 적용용 소재와 삽입 지침입니다. 원본 게임 HTML 및 전투 계산은 수정하지 않았습니다.
먼저 `preview/미리보기.html`을 열면 배경, 테두리, 병력과 이름표, 효과음 13종을 확인할 수 있습니다. 별도 서버나 인터넷 연결 없이 열립니다.
`docs/삽입위치_안내.png`의 번호는 아래 표와 대응합니다. 번호는 안내용이며 실제 게임 UI에 넣지 않습니다.

`integration/battle_theme.css`에 현재 선택자를 기준으로 한 스타일 예제를 제공했습니다. 외부 CSS로 사용하면 내부 이미지 경로는 이 CSS 파일 기준입니다. 게임 안에 CSS를 인라인으로 넣을 때는 이미지 URL을 data URL로 변환하거나 올바른 경로로 바꿔야 합니다.

### 중요: 전장 바닥은 CSS만 바꾸면 가려질 수 있습니다

58번의 `// src/ui/mass-battle-animation.js`에 있는 `MassBattleAnimation.tick()`은 `this.background` 캐시에 자체 땅색, 곡선, 얼룩을 그리고 그것을 캔버스 전체에 덮습니다. 이 부분을 함께 처리해야 새 바닥이 온전히 보입니다.

권장 A: `.mass-surface`에 새 배경을 표시하고 캔버스는 투명하게 유지합니다. `tick()`의 캐시 배경 생성 블록과 `ctx.drawImage(this.background,0,0)`만 제거·비활성화하고, `clearRect`와 병력·그림자·교전 효과 그리기는 유지합니다.

대안 B: 새 바닥을 미리 한 번 로드한 뒤 기존 `this.background` 캐시 안에 cover 비율로 그립니다. 매 프레임 이미지 생성·디코딩을 하지 않습니다. 이미지 로딩 전에는 기존 배경을 fallback으로 사용하고, 로딩 완료 시 캐시를 무효화합니다. DPR·창 크기 변경 시 다시 캐시합니다. 이미지는 게임 상태나 전투 판정에 관여하지 않습니다.

## 2. 코드 안에서 찾을 곳

배포 HTML의 바깥 12줄은 압축된 로더입니다. 아래 `src/...`는 파일 안의 원래 모듈 구분 주석입니다. 압축문자열을 직접 고치지 말고 원래 소스에서 적용한 뒤 다시 빌드하거나, 내부 HTML을 해제해 적용·검증 후 재패키징하세요. 줄 번호는 빌드마다 달라지므로 아래 함수명을 검색합니다.

| 작업 | 모듈 주석 / 검색할 이름 |
|---|---|
| 외곽·헤더·이름표·하단 재질 | CSS의 `.mass-battle`, `.mass-heading`, `.mass-controls`, `.mass-unit-label`, `.mass-surface` |
| 실제 전투창 구조 | `// src/ui/mass-battle-view.js` → `renderMassBattle()` |
| 기존 캔버스 바닥 처리 | `// src/ui/mass-battle-animation.js` → `MassBattleAnimation.tick()` |
| 첫 접촉·후퇴 등 발생 시각 | `massBattlePlan()`, `choreographMassArmy()`, `massBattleAt()` |
| 집단군 전용 단발음 큐 | `// src/audio/mass-battle-cues.js` → `massBattleSoundCues()` |
| 소리 데이터 등록 | `SOUND_PACK`, `new SoundMixer(...)`, `SoundMixer.buffer()` |
| 재생·정지·중복 방지 | `SoundDirector.sync()`, `pause()`, `reset()`, `suppressStage()` |

## 3. 효과음별 삽입 시점

모든 WAV는 48kHz·16bit·스테레오 원본입니다. OGG는 배포용입니다. 정확한 길이와 권장 gain은 `audio/audio_manifest.json`에 있습니다.

| 파일 ID | 길이 | 넣을 시점 | 상대 gain |
|---|---:|---|---:|
| `amb_wind_field_loop` | 12초·반복 | 전투창 진입~종료. 선택 사용, 아주 작게 | .10 |
| `foley_army_march_loop` | 6초·반복 | 실제 진격 동작이 보이는 동안. 첫 접촉 전에 줄임 | .34 |
| `sfx_first_clash` | 1.45초 | 양군 첫 실제 접촉. 집단전 전체에서 딱1회 | .68 |
| `amb_battle_distant_loop` | 12초·반복 | 하나 이상의 실제 교전이 보이는 동안 | .23 |
| `sfx_clash_metal_01~03` | 각 .68초 | 강조할 국지 타격만 선택. 모든 피해 틱에 붙이지 않음 | .36 |
| `sfx_shield_01~02` | 각 .58초 | 금속 타격과 번갈아 사용하는 둔탁한 타격 | .40 |
| `foley_retreat_01~02` | 각 2.25초 | 부대의 마지막 교전 이후 최종 후퇴 동작 시작 | .42 |
| `sfx_general_fallen` | 1.9초 | `scene.massCritical && scene.event.type==='death'` | .72 |
| `sfx_battle_end` | 2.2초 | 마지막 교전 종료에 1회. 잔향은 지도 전환까지 자연스럽게 | .30 |

gain은 음원 간 시작 비율입니다. 기존 게임의 master와 그룹 gain 뒤에서 적용하고 실제 녹화 내레이션에 맞춰 조정하세요. 미리보기의 개별 듣기는 음원 자체 음색을 확인하도록 같은 플레이어 음량으로 재생합니다. 전투 시연에서는 표의 비율로 믹스했습니다.

### 58번 데이터에서의 구체적인 연결

- 첫 충돌: 비자동 교전의 `visualContact ?? contact` 중 최솟값에 연결합니다. `plan.units` 각각에 붙이면 여러 번 울리므로 금지합니다.
- 지속 교전: `massBattleAt(plan,time).engagements`에서 `!automatic`인 교전이 존재할 때만 켭니다. 표시 시간은 `massBattleTime()` / `massGlobalTime()`과 동일한 시계를 사용합니다.
- 국지 타격: 기존 `plan.cues`의 `clash:<battleIndex>` 및 `result:<battleIndex>` 중 일부를 집단군 화면에서만 새 ID로 변환합니다. 원래 단발음과 새 단발음을 같은 사건에 겹쳐 내지 않습니다.
- 후퇴: 최종 교전 이후 만들어진 부대의 `orders` 중 `kind==='retreat'` 시작 시각을 사용합니다. 중간 패배, 단순 밀림, 왕의 연출상 복귀를 전부 후퇴음으로 처리하지 않습니다. 개인별 키를 사용해 한 번만 울립니다.
- 전사: 실제 `death` 사건만 사용합니다. 병력 0, `withdrawn`, 단순 비활성화를 전사로 해석하지 않습니다.
- 종료: 마지막 교전이 끝나면 bed를 약 .5~.8초에 걸쳐 줄이고 종료음을 재생합니다. `massPhase==='summary'`를 사용하면 결과 요약이 1초이므로 2.2초짜리 음원이 강제로 잘리지 않도록 별도 처리가 필요합니다. `scope:'stage'`로 잘라버리지 말고 지도 복귀까지 잔향만 허용하거나 짧은 페이드아웃을 합니다.
- 자동 점령만 있는 집단전: 진군만 사용하고 첫 충돌·지속 교전·후퇴음을 임의 생성하지 않습니다.

## 4. 반복음과 기존 재생기의 차이

58번 `SoundMixer.play()`는 `source.start(t,start,duration)`을 사용하며 `source.loop=true`를 설정하지 않습니다. `sustain:true`는 일시정지 복구용일 뿐 무한 반복 지원이 아닙니다. 반복 파일을 SOUND_PACK에 등록하는 것만으로 반복 재생이 완성되지 않습니다.

반복음은 기존 AudioContext와 master / battle 버스에 연결된 루프 소스로 재생하세요. `AudioBufferSourceNode.loop=true`를 사용하고 .3~.6초의 gain 페이드로 진입·퇴장합니다. 소스 상태는 기존 재생 컨트롤러에서 관리합니다. 별도의 setInterval로 전투를 진행시키지 않습니다.

- 한 번에 환경음 bed는 최대1개. 평상시 바람에서 교전 bed로 교체합니다.
- 진군음까지 포함한 반복 소스 최대2개. 첫 접촉 후 진군음을 정리합니다.
- 단발 타격은 최대2개. 전체 최대4소스의 예산을 기존 믹서와 함께 계산합니다. 별도 버스를 만든다고 무제한으로 소리를 추가하지 않습니다.
- 일시정지·건너뛰기·다시 보기·음소거·페이지 이탈 시 루프 정지 및 재개 위치를 처리합니다.
- 전사 등 중요음 재생 시 bed를 8~12dB 낮췄다가 복원합니다. 기존 중요음 ducking과 중복 감쇠하지 않도록 한 곳에서 처리합니다.
- 4×·8×에서도 소리 자체의 pitch를 올리거나 모든 타격을 몰아 재생하지 않습니다. 일반 타격을 줄이고 첫 충돌·최종 후퇴·전사만 우선합니다. 짧은 장면에서도 단발음 최소 청취 길이 .15~.30초를 확보하되 다음 장면에 무한 잔류시키지 않습니다.

## 5. 데이터 등록 예제

`integration/battle_pack_data.js`에는 이미지와 OGG가 data URL로 들어 있습니다. 단일 HTML로 빌드할 때 옮기기 편하도록 제공했습니다. 전투 엔진을 실행하는 코드는 없습니다.

```js
// battle_pack_data.js 로드 후, SoundMixer를 만들기 전에 수행.
const materialPack = window.SAGUK_BATTLE_PACK;
const extraSounds = Object.values(materialPack.audio).map(a => ({
  id: a.id, label: a.title, category: a.category,
  duration: a.duration, volume: a.recommendedGain,
  cooldown: a.loop ? 0 : 180, priority: 0, data: a.data
}));
const soundMixer = new SoundMixer({
  sounds: [...SOUND_PACK, ...extraSounds],
  settings: loadSoundSettings(localStorage)
});
```

위는 데이터 등록 예제이며 반복·상태 동기화 구현을 대신하지 않습니다. 현재 버스 그룹은 `movement`, `battle`, `important` 등을 사용합니다. manifest의 `ambience`는 파일 분류이므로 `cue.group`에 그대로 넣지 말고 기존 `battle` 버스로 연결하세요. 새 ID에는 기존 SOUND_LEVEL_GAINS가 없으므로 기본1을 사용하고 gain을 중복 곱하지 마세요.

## 6. 텍스처 마감 및 사용 범위

- `*_source_512.webp`는 재질 원본입니다. 반복 사용은 `*_seamless.svg`를 사용하세요. 네 사분면을 대칭 연결해 맞닿는 경계를 동일하게 구성했습니다. 원본 이미지를 그냥 반복해서 생기는 경계선을 피합니다.
- SVG에는 원본 재질이 포함돼 있어 외부 이미지 연결이 끊기지 않습니다.
- `frame_nineslice.svg` 및 PNG는 가운데가 투명합니다. 별도 흰 배경이 붙지 않습니다. PNG도 slice32로 사용합니다.
- 전장 배경은 한 장을 cover로 사용하며 타일링하지 않습니다. PNG와 WEBP는 동일한 2048×1152 내보내기이며 이미지 생성 원본보다 새로운 디테일이 추가된 업스케일은 아닙니다.
- 미리보기의 병력 이미지는 사용자 제공 58번 게임의 기존 스프라이트입니다. 새로운 병력 아트로 납품하는 것이 아닙니다.
- 새 배경·재질은 이 요청을 위해 생성했고, 효과음은 외부 녹음·상용게임 샘플·음악·사람 목소리 없이 직접 합성했습니다. 자세한 출처는 `docs/제작출처.txt`에 있습니다.

## 7. 적용 후 확인할 것

1. 전투 바닥이 기존 캔버스 배경에 가려지지 않는지 확인.
2. 작은 창·전체 화면·DPR2에서 프레임 모서리, 이름표 글자, 실제 병력의 대비 확인.
3. 1×·4×·8×, 일시정지·재개·건너뛰기·다시 보기에서 반복음 중복과 잔류 확인.
4. 왕 참전·전사·무승부·무방비 점령·수도 함락에서도 사실과 다른 소리가 나지 않는지 확인.
5. 기존 저장 데이터·게임 RNG·전투 결과·영토 변화가 소재 적용 전후 동일한지 확인.

원본 게임에 대한 통합 검증은 적용 후 별도로 해야 합니다. 이 팩의 검수 기록은 `docs/검수결과.json`에 포함합니다.
