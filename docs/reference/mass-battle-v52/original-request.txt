집단군 전투를 자동으로 연출하는 기능을 실제로 구현해줘. 첨부한 병력 꾸러미 시안은 원하는 화면과 움직임을 설명하기 위한 참고자료다.
핵심은 기존 전투 결과를 그대로 유지하면서, 이미 계산된 여러 교전을 하나의 이어지는 집단전처럼 보여주는 것이다.
계획이나 설명만 제시하고 끝내지 말고, 현재 소스를 분석한 뒤 실제 코드 수정과 검증까지 진행해줘. 일반적인 구현 선택은 직접 판단하되, 전투 규칙에 영향을 주는 변경은 하지 마.
1. 작업 목표
현재는 집단군 전투에서도 지휘관끼리 개별적으로 싸우고 결과를 보여주는 과정이 반복된다.
이를 다음과 같이 바꾸고 싶다.
- 양측 병력 꾸러미가 전장에 진형을 갖춰 등장한다.
- 여러 부대가 함께 접근하고 교전한다.
- 교전이 계속되는 동안 부대별 병력이 서로 다른 시점에 조금씩 감소한다.
- 일부 부대가 적을 격퇴하거나 패배해 후퇴하는 동안 다른 부대는 계속 싸운다.
- 남은 부대가 전진하거나 좌우로 벌어지고, 측면으로 돌아 들어가며 적을 압박하는 모습을 보여준다.
- 마지막 교전이 끝난 뒤 전체 공세 결과를 짧게 정리한다.
전투의 준비·진행·전황 변화·종결이 한 화면 안에서 자연스럽게 이어져야 한다.
첨부 시안의 ‘진형 대치 → 양군 진격 → 정면 교전 → 좌익 진격 → 양익 전개 → 측면 압박 → 방어선 붕괴 → 전투 종결’은 가능한 전개 중 하나다. 모든 전투에 이 순서를 고정 적용하지 마.
2. 반드시 보존할 기존 전투 시스템
다음 항목은 현재 게임의 계산과 결과를 그대로 유지해줘.
- 주사위 면수, 주사위 결과, 보정치, 난수 사용 순서
- 공격·방어 대상과 교전 순서
- 연속전, 추가 진격, 구원, 역공
- 병력 손실과 최종 잔존 병력
- 승리 횟수, 경험치 등 기존 누적 값
- 피로, 혼란, 정비 등 기존 상태
- 지휘관의 후퇴·전사·교체
- 실제 지도상의 위치와 이동 거리
- 영토 점령, 수도 함락, 국가 멸망, 최종 게임 결과
전투 결과는 기존 엔진이 계산한다. 새 기능은 그 기록을 읽어 화면에 보여줄 계획을 만든다.
포위하거나 측면으로 돌아가는 모습은 연출용 움직임이다. 포위 보정, 측면 공격 보너스, 새로운 사기 판정, 새로운 전투 AI 등을 추가하지 마.
화면에서 부대를 이동시키기 위해 실제 게임의 위치·피로·이동 거리를 변경해서도 안 된다.
3. 화면 구성
지휘관 카드 대신 기존 게임에 들어 있는 병사 그림과 애니메이션을 활용해 ‘부대별 병력 꾸러미’를 표시해줘.
- 지휘관 한 명이 지휘하는 부대를 하나의 꾸러미로 구분한다.
- 꾸러미 근처에는 지휘관 이름, 현재 병력, 간단한 잔존 병력 막대를 표시한다.
- 큰 초상화 카드와 개별 대결표가 전투 화면의 중심이 되지 않게 한다.
- 기존 병사 등급과 국가색·공수 구분 체계를 가능한 한 활용한다.
- 국가색 깃발은 추가하지 않는다.
- 병사 그림의 방향과 이동·교전 방향이 자연스럽게 연결되게 한다.
- 병력이 줄면 숫자와 막대가 감소하고, 꾸러미의 병사 수도 적절히 줄어들게 한다.
- 화면에 그리는 병사 수는 표현용이다. 실제 병력 숫자가 기준이며, 병사 그림 수로 손실을 다시 계산하지 않는다.
- 많은 부대가 등장해도 실제 참가 부대가 임의로 누락되지 않도록 한다.
첨부 시안의 우측 설명란과 하단 규칙·설명 영역은 넣지 마. 전투 화면을 넓게 사용해줘.
게임 화면에는 필요한 정보만 둔다.
- 양측 국가명 또는 진영 구분
- 양측 현재 병력 합계
- 부대별 이름과 병력
- 필요한 순간의 ‘격퇴!’, ‘후퇴’, ‘전사’ 등 짧은 표시
- 기존 재생 조작과 연결되는 최소한의 버튼
- 전투 종료 후 상세 기록과 지도 복귀
‘연출 시안’, ‘설계 메모’, ‘계산된 결과를 재생 중’ 같은 개발 설명은 실제 게임 화면에 넣지 마.
4. 완성된 대본 목록 대신 자동 조합 기능을 구현
완성된 전투 대본을 수십·수백 개 하드코딩하는 방식은 피하고, 다음 구조로 구현해줘.
전투 기록 분석 → 가능한 전개 유형 평가 → 유형 선택 → 부대 역할 배정 → 행동 조합 → 시간표 작성 → 화면 재생
프로그램 자체가 전투 기록을 읽고 연출을 구성해야 한다. 실행 중 ChatGPT나 외부 AI API를 호출하는 방식은 사용하지 마.
처음에는 다음 네 가지 전개를 중심으로 구현하면 된다.
- 정면 돌파형
- 양익 압박형
- 접전형
- 방어군 반격형
각 유형은 완성된 고정 대본이 아니라, 어떤 움직임을 우선 사용할지 정하는 틀로 만들어줘.
예를 들면 다음과 같다.
- 정면 돌파형: 정면 교전을 유지하다가 실제 승리한 부대가 열린 공간으로 전진한다.
- 양익 압박형: 중앙 교전을 유지하면서 이동 가능한 부대가 측면으로 돌아 들어간다.
- 접전형: 승패와 손실이 엇갈리는 기록에 맞춰 전선이 조금씩 밀고 밀린다.
- 방어군 반격형: 실제 방어 성공·역공 기록에 맞춰 수비군이 전진하고 공격군이 밀려난다.
조건에 맞는 후보가 여러 개면 전투 기록에서 만든 별도 연출 시드를 이용해 선택할 수 있게 해줘. 동일한 게임 결과에도 가능한 연출이 여러 가지 나오되, 같은 기록과 같은 연출 시드로 다시 보면 동일하게 재생되어야 한다.
연출용 난수는 게임 판정용 난수와 완전히 분리해줘.
5. 전투 기록에서 분석할 정보
최소한 다음 정보를 활용해줘.
- 양측 실제 부대 구성과 참가 지휘관
- 각 부대의 시작 병력과 종료 병력
- 각 개별 교전의 승패와 손실
- 한 지휘관이 여러 번 싸웠는지 여부
- 초반·중반·후반의 교전 결과 변화
- 후퇴·전사·역공·추가 진격 등의 중요 사건
- 실제 돌파·방어·점령 결과
- 연출 중 계속 활동할 수 있는 부대와 최종 이탈한 부대
개별 교전에서 공격·방어 역할이 바뀌는 역공도 원래 진영과 지휘관 정체성을 유지해 처리해줘.
전체 결과를 단순히 ‘개별 승수가 많은 진영’이나 ‘남은 병력이 많은 진영’으로 새로 판정하지 마. 기존의 실제 공세·점령 결과를 따르고, 전체 승패를 명확히 정의하기 어려운 경우에는 ‘공세 종료’와 실제 전과를 표시하면 된다.
6. 부대 역할과 기본 행동
중앙·좌익·우익·후속 부대 등은 화면상의 역할로 배정해줘. 이 역할은 실제 능력치에 영향을 주지 않는다.
부대 수와 결과에 따라 역할을 조정하고, 없는 부대를 새로 만들어내지 마. 한 부대를 두 부대처럼 복제해 양익을 채우는 방식도 사용하지 마.
다음과 같은 기본 행동을 조합할 수 있게 해줘.
- 진형 배치와 대기
- 정면 접근
- 전선 유지와 교전
- 좌우로 벌어지기
- 측면 선회
- 피격과 짧은 흔들림
- 조금 밀려나기
- 열린 공간으로 진입
- 압박 범위 좁히기
- 후퇴와 전장 이탈
- 전사
- 교전 종료와 정리
각 행동은 대상 부대, 시작 시각, 지속 시간, 시작·종료 위치, 이동 방향, 이동 폭 등을 받아 재사용할 수 있게 한다.
예를 들어 ‘측면 선회’ 하나로 좌익·우익의 다른 부대가 서로 다른 거리와 속도로 움직일 수 있어야 한다.
이동은 시간에 따라 이어지는 경로로 처리하고, 매 프레임 무작위 좌표를 새로 정하거나 부대가 순간이동하는 모습은 피한다.
부대 꾸러미 내부 대열도 필요하면 행군할 때 좁아지고, 맞붙을 때 펼쳐지는 정도로 조정해줘. 과도한 물리 시뮬레이션이나 병사 개개인의 전술 판단은 필요 없다.
7. 여러 부대의 행동이 겹쳐 진행되게 구현
다음처럼 한 화면에서 여러 일이 함께 일어나야 한다.
- 중앙 부대는 계속 교전한다.
- 좌익 부대는 측면으로 이동한다.
- 다른 부대에서는 타격과 병력 감소가 발생한다.
- 먼저 패배한 부대는 후퇴한다.
- 남아 있는 부대는 계속 진격하거나 압박한다.
한 부대의 접근·주사위·피격·결과를 모두 보여준 뒤 다음 부대로 넘어가는 순차 대결을 기본 연출로 남겨두지 마.
다만 같은 지휘관의 실제 교전 기록에 인과관계가 있으면 그 순서를 지켜줘. 서로 독립적인 부대의 움직임과 효과를 겹쳐 보여주는 방식으로 구성하면 된다.
한 부대에 서로 충돌하는 이동 명령을 동시에 주지 않도록 하고, 후퇴·전사·피격·공격·대기 사이의 우선순위를 정해줘.
8. 병력 감소와 중간 승패 표시
병력 감소는 기존 기록의 실제 손실량을 바탕으로 한다.
- 타격 시점마다 실제 손실량을 나누어 표시한다.
- 현재 병력과 잔존 병력 막대를 함께 갱신한다.
- 감소량은 해당 꾸러미 근처에 잠깐 띄운다.
- 같은 피해를 여러 번 차감하지 않는다.
- 마지막에는 기존 엔진이 계산한 최종 병력과 정확히 일치해야 한다.
- 실제 수치의 정밀도와 반올림 방식은 기존 게임을 따른다.
한 지휘관이 적 하나를 이기고 다음 상대와 계속 싸운다면 ‘격퇴!’ 같은 짧은 표시만 띄우고 교전을 이어가게 해줘.
다음 교전이 남아 있는데 미리 ‘전투 종료’로 표시하거나 부대를 전장에서 제거하지 마.
이후 교전에서 패배하면 실제 기록에 맞춰 후퇴 상태로 전환한다. 앞에서 적을 격퇴했던 부대가 나중에 패배하는 모습도 자연스럽게 표현되어야 한다.
전사는 실제 전사 기록이 있을 때만 표시해줘. 병력이 0이 되었다는 이유만으로 지휘관을 자동 전사 처리하지 마.
실제 교전하지 않은 대기·예비 부대를 표시한다면, 그 부대에 가짜 손실이나 격퇴 기록을 만들어 붙이지 마.
9. 조합 조건과 예외 처리
다음 조건을 고려해 자연스럽게 다른 전개를 선택하도록 해줘.
- 양익으로 이동할 부대가 부족하면 정면 교전 중심으로 구성한다.
- 공격군이 패배하는 전투에도 무조건 포위 성공 연출을 적용하지 않는다.
- 이미 최종 이탈한 부대를 다시 교전에 투입하지 않는다.
- 계속 교전할 기록이 있는 부대는 중간 승리 이후에도 활동을 유지한다.
- 1대1, 1대다수, 다수대1에서도 없는 부대를 만들지 않고 표시한다.
- 무방비 영토 점령에서는 존재하지 않는 적과 싸우는 모습을 만들지 않는다.
- 멀리 떨어진 별개 전선과 다른 집단군을 임의로 하나의 전장에 합치지 않는다.
- 같은 집단군의 추가 진격·역공을 이어 보여줄 때는 전황의 연결이 이해되게 한다.
- 전투가 일찍 종료된 경우 억지로 긴 교전 장면을 채우지 않는다.
- 조합 가능한 움직임이 부족한 경우에는 실제 기록에 맞는 단순한 정면 교전으로 안전하게 처리한다.
포위는 우세한 전황을 표현하는 여러 연출 중 하나다. 승리하는 전투가 모두 같은 포위 장면이 되지 않게 해줘.
10. 재생 시간과 시점
전투가 어느 정도 이어지는 느낌을 주되, 부대 수만큼 개별 연출 시간이 계속 더해지지는 않게 해줘.
- 보통 규모의 집단군 전투는 기본 배속에서 약 12~18초를 초기 기준으로 잡는다.
- 소규모·무방비 점령은 더 짧게 처리한다.
- 참가 부대 수와 중요한 사건 수를 고려하되 과도하게 길어지지 않도록 상한을 둔다.
- 실제 플레이를 보며 조정하기 쉽도록 시간과 이동 폭을 설정값으로 모아둔다.
- 같은 모션을 반복하는 시간만 늘리지 말고, 손실·격퇴·후퇴·진격 등의 변화가 전투 중 계속 드러나게 한다.
한 전투 동안 시점을 안정적으로 유지하고, 기존 시점 고정 설정을 존중해줘. 참가 부대 수가 달라져도 이름과 병력 숫자를 읽을 수 있도록 배치를 조정한다.
11. 기존 재생·지도·상세 기록과의 연결
새 연출은 기존 재생 구조와 연결해야 한다.
- 시작·일시정지·재개·배속 변경이 정상 작동해야 한다.
- 기존에 지원하는 건너뛰기·다시 보기·촬영 관련 기능이 있다면 유지한다.
- 일시정지와 재개 시 부대 위치·병력 표시·애니메이션 진행이 이어져야 한다.
- 다시 보기에서는 같은 기록으로 동일한 연출을 재생한다.
- 효과음은 기존 재생 기능을 활용하고, 여러 부대 때문에 과도하게 중첩되지 않게 한다.
- 정지·탐색·재개 때문에 같은 효과음이 중복 재생되지 않게 한다.
전투 시작 상태와 해당 전투 묶음의 종료 상태를 정확히 사용해줘. 한 턴 전체의 최종 상태를 너무 일찍 보여줘서, 뒤에 발생할 충원·다른 전투·정산 결과가 먼저 노출되지 않도록 한다.
전투 연출이 끝난 뒤에는 실제 지도상의 부대 위치·영토·병력과 정확히 연결되어야 한다.
전투 화면을 바꾼 뒤에도 지도에서 기존 개별 전투 장면이 다시 차례로 재생되어 같은 전투를 두 번 보는 문제가 생기지 않게 해줘. 기본 관전 흐름은 새 집단전 연출로 통합한다.
실제 주사위, 보정, 개별 교전 순서와 결과는 ‘상세 기록’에서 확인할 수 있도록 보존해줘.
12. 현재 소스 분석과 구현 구조
현재 소스를 먼저 확인하고 기존 구조를 최대한 활용해줘.
첨부한 55번 HTML에서는 전투 계산, 사건 기록, 장면 구성, 화면 재생이 나뉘어 있었다. 현재 소스에도 존재한다면 다음 부분을 우선 확인해줘.
- resolveContinuousCampaign
- campaignGroups
- compactCampaignScenes
- cohortMapScenes
- renderCampaignOverlay
- TurnPlayback
- TroopAnimation
- TROOP_ART
이 이름이 현재 소스와 다르면 실제 구조에 맞춰 적용해줘.
구현은 가능하면 다음 책임으로 나눈다.
- 전투 기록을 분석하는 부분
- 전개 유형을 선택하고 부대 역할을 정하는 부분
- 움직임·타격·손실·이탈을 시간표로 만드는 부분
- 현재 재생 시각의 부대 위치·병력·상태를 구하는 부분
- 기존 병사 그림으로 화면을 그리는 부분
연출 계획은 같은 입력에 같은 결과가 나오게 만들고, 화면을 그리는 과정이 게임 상태나 판정 난수를 변경하지 않게 해줘.
실제 원본 소스 프로젝트가 있으면 원본 소스를 수정하고 배포 파일을 생성한다. 첨부 파일이 압축된 단일 HTML이면 내부 구조를 해제해 분석한 뒤, 기존 이미지·폰트·사운드 등 필요한 자원을 유지한 실행 가능한 단일 HTML로 만들어줘.
참고 시안의 인명·병력·배치·시간을 실제 플레이에 하드코딩하지 마. 시안은 연출 방향을 보여주는 예시다.
13. 성능과 표시 품질
기존 병사 이미지와 프레임 캐시를 재사용하고, 부대마다 동일 이미지 데이터를 중복 생성하지 않도록 해줘.
- 많은 부대에서도 화면이 과도하게 느려지지 않게 한다.
- 전투를 반복해도 이미지·타이머·이벤트·애니메이션 자원이 계속 쌓이지 않게 한다.
- 이름, 병력, 손실 팝업이 다른 부대나 화면 밖에 가려지지 않도록 배치한다.
- 밀집된 상황에서는 표시용 병사 수와 배치 간격을 조정하되 실제 병력은 유지한다.
- 시각적인 장식보다 부대 움직임, 수치의 정확성, 가독성을 우선한다.
- 전투 외의 지도·편집·저장 화면은 이번 작업에 필요한 범위에서만 수정한다.
14. 검증
가장 중요한 검증은 같은 초기 상태·같은 게임 시드에서 원본과 수정본의 실제 시뮬레이션 결과가 같은지 확인하는 것이다.
가능한 범위에서 여러 턴을 진행해 다음을 비교해줘.
- 실제 주사위와 난수 상태
- 교전 기록
- 지휘관의 병력·상태·전적·위치
- 영토 소유권과 점령 결과
- 최종 게임 결과
연출용 데이터 추가를 제외하고 기존 판정 결과가 달라지면 수정해줘.
또한 다음 상황을 확인해줘.
- 1대1, 1대다수, 다수대1
- 양측 여러 부대가 참가하는 전투
- 한 지휘관의 연속 승리
- 중간에 승리한 지휘관의 이후 패배
- 공격군 일부 패배 후 나머지 부대의 돌파
- 방어 성공·역공
- 무승부와 무방비 점령
- 후퇴·전사·국가 멸망
- 많은 부대가 등장하는 경우
- 일시정지·재개·배속 변경·반복 재생
- 전투 종료 후 지도 상태 연결
실제 전투 기록을 이용해 확인하고, 예시 데이터만 움직이는 데모로 끝내지 마. 실행하지 못한 검증은 완료했다고 보고하지 말고 구분해서 알려줘.
15. 완료 결과물
이번 작업의 목표는 다음 조건을 갖춘 첫 구현본이다.
- 기존 전투 판정 유지
- 병력 꾸러미 중심의 집단군 전투 화면
- 결과에 따라 선택되는 네 가지 기본 전개
- 여러 부대의 교전·이동·손실이 겹쳐 진행되는 연출
- 진격·양익 전개·측면 압박·후퇴
- 점진적인 병력 감소와 정확한 최종 결과
- 우측 설명란·하단 규칙란 제거
- 기존 재생 기능과 지도 복귀 연결
작업이 끝나면 실행 가능한 수정본과 함께 다음을 간단히 보고해줘.
- 수정한 주요 부분
- 실제 구현한 전개 유형과 선택 조건
- 원본 판정과 동일함을 확인한 방법
- 실행한 검증과 남은 제한 사항
- 대표적인 전투 진행 장면
파일로 작업한다면 원본을 보존하고 수정본을 별도 이름으로 제공해줘. 기존 소스 저장소에서 작업한다면 수정 내역을 추적할 수 있게 남겨줘.
