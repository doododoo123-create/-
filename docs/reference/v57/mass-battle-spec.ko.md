# 사국쟁패 집단군 전술화면 개편 과업지시서

## 1 과업 목적과 최우선 범위

기준 파일은 첨부한 「사국쟁패 Studio (61).html」이다. 기존 60번 기준 지시서는 이 문서로 대체한다. 이 작업은 집단군 전술화면 안의 표현만 개편하는 실제 구현 요청이다. 코드 조사, 구현, 검증, 실행 파일 제출까지 수행해라. 게임 규칙과 다른 시스템, 지도 화면을 개선하는 과업으로 확대하지 마라.

사용자가 최우선으로 원하는 것은 전투의 흐름을 읽을 수 있는 지속적인 연출이다. 양군이 한 번 접근해 싸우고 마지막에 결과를 모아서 공개하는 방식으로 끝내지 마라. 같은 전술화면이 유지되는 동안 전선이 형성되고, 실제 개별 승패가 드러나고, 승리 부대의 진격과 후속 방어, 실제 점령과 재탈환, 반격과 철수가 이어져야 한다.

전투 화면은 이미 확정된 기록을 재구성하는 읽기 전용 재생 화면이다. 전술 연출이 새로운 승패, 피해, 포위 보정, 영토 변화나 지휘관 행동을 게임 코어에 추가하면 안 된다. 실제로 없었던 역전이나 재탈환으로 장면을 길게 만들지 마라.

목표는 다음 다섯 가지다.

1. 접근, 접촉, 공격, 피격, 실제 병력 손실 공개를 하나의 교전 사건으로 연결한다.
2. 아래 14개 전술을 서로 구별되는 경로, 전열 변화, 접촉 면과 상대 대응으로 구현한다.
3. 지휘관 수와 병력 수가 극단적으로 달라도 규모, 배치, 접촉과 후퇴가 성립한다.
4. 원래 기록의 여러 교전을 하나의 지속되는 전술화면 안에서 이어 보여준다. 개별 대결 화면을 반복하지 않는다.
5. 누가 누구를 이겼고 졌는지, 누가 어떤 영토를 점령하고 다시 되찾았는지를 결과 발생 순간에 읽을 수 있게 한다.

변경 허용 범위는 3절, 연속 전개와 기록 공개의 핵심 요구는 21~23절, 범위 보존 검증은 24절을 반드시 확인해라. 시간이 부족하더라도 이 요구를 빼고 전술 문구만 추가한 결과물을 완료로 제출하지 마라.

원본 HTML은 보존하고 수정 실행 파일을 별도로 제출해라. 압축된 단일 HTML이면 실제 코드와 자산을 풀어 조사하고 같은 방식으로 다시 묶어라. 게임을 실행하는 데 새 외부 API나 유료 서비스를 요구하지 마라. 현재 사용 중인 병사 이미지, Canvas, 배경과 효과음을 우선 재사용한다.

이 문서의 시간과 표시 밀도는 25절의 사용자 확정 기준을 따른다. 사용자는 일반 집단군 30~45초, 복잡한 진격과 반격 60~90초라는 추천안을 채택했다. 같은 선택을 다시 확인하지 말고 구현해라. 사용자가 이후 별도 값을 전달하면 그 값으로 조정하되 다른 시스템까지 수정하지 마라. 일반적인 구현 선택은 직접 진행하고, 범위를 넓혀야만 가능한 제안은 실제 코드에 적용하지 말고 별도 제안으로 남겨라.

61번의 전술화면은 아직 다음 특성이 있다.

- 한쪽 교전 지휘관이 3명 미만이면 6초, 나머지는 표시 인원 수에 따라 16초 또는 18초다.
- 한 번 접근한 뒤 대부분 비슷한 전선에서 싸우고 마지막 교전 승패에 따라 전진하거나 후퇴한다.
- 실제 개별 교전의 resolve를 기본 길이의 82퍼센트 시점으로 모아 둔다.
- 최종 병력 차이를 대체로 다섯 번 나눠 공개한다. 원래 각 교전의 피해와 화면 타격이 직접 연결되지 않는다.
- 전술화면 상단 전장 제목은 현재 전개에 따라 실제 교전 순서대로 바뀌는 구조가 아니다.
- 종료 요약의 gained, lost는 묶음 전후 소유권의 순변화다. 같은 영토가 넘어갔다가 돌아오면 중간 점령 사건을 이 값만으로 복원할 수 없다.
- 원래 records에는 개별 battles, events, frames, takenTerritoryIds와 실제 소유권 변경을 읽을 자료가 있다. 이를 새 규칙 없이 전술화면의 전개 자료로 사용할 수 있다.
- 61번에는 mapReveal과 mapAfterReveal을 통해 지도 공개 순서를 보존하는 처리가 있다. 전술화면을 길게 만든다는 이유로 이 처리를 삭제하거나 지도 상태를 조기에 공개하지 마라.

현재 상위 재생 경로는 집단군 표시 옵션과 전술화면 옵션이 켜져 있고 기존 filming 분기가 아닌 경우 massBattleScenes를 사용한다. 이 활성 조건, 다른 모드의 선택 분기와 기존 촬영 모드는 그대로 유지해라.

## 3 수정 범위와 절대 보존 경계

### 3.1 허용되는 변경

집단군 전술화면이 실제로 열려 있는 동안 사용하는 다음 요소만 수정해라.

- 전술화면 전용 읽기 어댑터, 연출 계획, 내부 시간표와 기록 공개 순서.
- 전술화면 안의 병력 축척, 구획, 대열, 움직임, 접촉, 방향 전환, 손실과 상태 표시.
- 14개 전술의 적용과 상대 대응, 전술 간 전환.
- 전술화면 내부의 현재 교전 안내, 개별 승패 표시, 영토 소유권 흐름 표시와 종료 요약.
- 전술화면 내부의 접촉 효과음 발생 시각과 중복 방지. 기존 자산과 공용 재생 API를 사용한다.
- 전술화면 계획을 기존 재생기에 넘기는 데 불가피한 최소 연결 코드. 다른 장면의 분기, 시간과 결과는 바꾸지 않는다.

전술화면 내부 시간표가 길어지는 것은 허용된다. 그 외 모든 장면과 시스템은 61번을 기준으로 유지한다.

### 3.2 변경 금지

- engine 및 model의 규칙과 계산, 주사위, 보정치, AI 행동, 공격 목표, 지휘관 동원과 집단군 구성.
- 병력 충원, 이동 거리, 보급, 고립, 피로, 혼란, 패전 재참전, 사망, 등용과 세대 관리.
- 실제 승패, 교환비, 각 교전의 피해, 세계 상태, 실제 영토 소유권과 수도 및 멸망 처리.
- 국가, 장수, 지도 편집과 초기 세계 설정.
- 실제 턴과 계절 진행, 세이브, 불러오기, 기록 포맷과 기존 시드.
- 지도 렌더링, 지도 공개 시점, 지도 위 병력 위치, 카메라, 줌과 시점 고정.
- 전술화면 전후의 집결, 지도 행군, 전장 도착, 지도 후퇴, 점령 애니메이션과 지도 복귀.
- massBattleRecap, mapReveal, mapAfterReveal 및 기존 지도 누적 공개 장부의 의미와 처리 순서.
- campaignGroups와 isArmyCampaign의 집단군 화면 대상 선정 및 묶음 경계.
- 일반 일대일 전투 화면과 다른 전투 모드, 공용 촬영 모드, 전역 재생 및 배속 정책.
- 공용 오디오 믹서, 새 BGM, 전역 효과음 정책, 이번 과업과 무관한 배경 및 텍스처 교체.

원래 외부 지도 장면이 중복처럼 보이더라도 이번 작업에서 제거하거나 통합하지 마라. 전술화면 안에서 읽기 전용으로 점령을 설명하고, 밖의 실제 지도 연출은 61번 그대로 이어져야 한다. 다른 시스템의 버그를 발견하면 수정하지 말고 별도 참고 사항으로 보고해라.

### 3.3 원본 데이터 계약

같은 세계와 입력에서 주사위, 보정치, 교전 참여자, 승패, 피해, 병력, 장수 생사, 영토, 후퇴 목적지와 다음 턴 게임 난수 상태가 개편 전후 같아야 한다. 원본 world, record, events와 frames를 수정하지 마라. 연출 계획은 읽기 전용으로 참조하거나 필요한 필드만 복사한다.

전술화면 내부에 표시용 소유권과 위치 장부를 새로 두어도 되지만 원본 지도 장부를 복사해 별도 객체로 사용해라. 이 객체를 지도 렌더링이나 저장 상태로 전달하지 마라. plan.before, plan.after, plan.group, 기존 changes와 engagements의 원본 식별 계약을 깨지 말고 필요하면 별도 story 필드에 전개 정보를 넣어라.

### 3.4 인과관계와 화면 제약

같은 지휘관의 연속 교전, 손실, 실제 증원과 전사, 같은 영토의 소유권 변경은 원래 순서를 지켜라. 독립적인 부대의 접근과 교전은 서로 겹쳐 보여줄 수 있다. 전체 결과를 한 시점에 몰아 공개하거나 마지막 결과만 남기지 마라.

병력 꾸러미 중심 화면을 유지하고 지휘관 카드 일대일 대결로 되돌리지 마라. 우측 설명란과 하단 규칙 안내란, 긴 공략 패널을 추가하지 마라. 새 국가색 깃발을 만들지 마라. 짧은 현재 교전 문구와 작은 영토 표시줄은 전술화면 상단 기존 제목 영역에 통합하고, 부대 위 이름과 병력은 유지한다.

전술화면 바깥 CSS에 영향이 없도록 선택자를 mass-battle 등 해당 화면 루트로 한정해라. 공용 버튼과 패널의 전역 스타일을 바꾸지 마라.

## 4 지휘관과 화면상 병력 구획을 분리해라

### 4.1 두 가지 단위

실제 지휘관 단위와 화면상 병력 구획을 구분해라.

- 실제 지휘관 단위: 원본 ID, 소속, 병력 장부, 승패, 생사, 교전 관계를 보유한다.
- 화면상 병력 구획: 한 지휘관의 병력을 여러 대열로 표현하기 위한 이동 및 그리기 단위다.

한 지휘관이 많은 병력을 이끌면 여러 구획으로 표현할 수 있다. 이는 새 지휘관, 새 전투 부대, 추가 공격권이 아니다. 모든 구획은 원본 지휘관 ID를 부모로 참조해야 한다. 구획의 표시 가중치는 합계 1이어야 하고, 실제 병력 장부는 지휘관에게 하나만 존재해야 한다.

구획의 면적과 병사 배치는 시각적 가중치로 나누어도 되지만 소수점 병력을 새 게임 병력처럼 생성하지 마라. 실제 병력 숫자와 손실은 원래 규칙 단위를 따른다. 이름표는 지휘관의 대표 구획에 연결하고 동일 인물이 여러 명인 것처럼 이름표를 복제하지 마라.

1만짜리 작은 부대는 기본적으로 작은 구획 하나로 표현해라. 작은 부대를 중앙, 좌익, 우익, 예비대 네 군대로 쪼개지 마라. 반대로 지휘관 한 명이 60만을 보유하면 한 덩어리에 몰아 그리지 말고 넓은 전열과 후속 대열로 나눌 수 있어야 한다.

### 4.2 병사 그림 축척

한 전투의 양군은 같은 축척으로 병사 그림 수를 배정해라. 지휘관 한 명마다 최소 8개를 배정하는 현재 방식은 교체해라.

초기 기준값 예시는 큰 쪽 진영에 최대 약 480개의 병사 그림을 배정하는 것이다. 이 값은 성능 검증으로 조정할 수 있다. 다만 축척은 진영별로 따로 정하지 말고 해당 전투 전체에 공통 적용해라.

| 실제 총병력 | 목표 그림 수 예시 |
| --- | --- |
| 5만 대 30만 | 약 80개 대 480개 |
| 60만 대 1만 | 약 480개 대 8개 |
| 60만 대 60만 | 약 480개 대 480개 |

그림 수는 실제 병력 수를 전부 복제하는 것이 아니다. 극소수 병력이 식별되지 않는 경우 최소 표시 크기를 허용하되, 실제 숫자는 정확히 유지하고 대군보다 커 보이지 않게 해라. 상한과 최소값으로 생기는 오차는 개발 검증 정보에 남겨라.

성능 때문에 그림 수를 낮추면 양쪽에 동일한 기준을 적용해라. 전체 병사 수 예산을 먼저 정하고 지휘관에게 비례 배분하는 방식으로 계산해라. 정수 반올림 잔여는 결정적으로 분배하고, 지휘관 수가 많다고 총 그림 수가 증가하지 않게 해라.

대군의 존재감은 병사 크기 확대보다 전열 폭, 대열 깊이, 후방 병력으로 표현해라. 전장이 작아지면 이름표 충돌과 최소 표시 크기도 함께 처리해라.

## 5 통합 연출 계획의 구조

아래는 권장 개념 구조다. 프로젝트 언어와 스타일에 맞게 바꿔도 되지만 정보와 책임은 유지해라. 이 스키마는 완성 코드가 아니라 구현해야 할 계약의 예시다.

```ts
type BattlePresentationPlan = {
  version: number;
  seed: number;
  durationMs: number;
  commanders: CommanderView[];
  groups: VisualGroup[];
  tactics: TacticInstance[];
  motions: MotionTrack[];
  contacts: ContactWindow[];
  reveals: RevealEvent[];
  importantEvents: ImportantEvent[];
  ledger: PresentationLedger;
  story: TacticalStory; // 전술화면 전용 전개와 표시용 영토 장부
};

type VisualGroup = {
  id: string;
  commanderId: string;
  side: 'attack' | 'defense';
  weight: number;
  role: 'center' | 'left' | 'right' | 'reserve' | 'support';
  footprint: { width: number; depth: number };
  formationShape: string;
};

type ContactWindow = {
  id: string;
  sourceBattleIds: string[];
  groupAId: string;
  groupBId: string;
  startMs: number;
  endMs: number;
  faceA: 'front' | 'left' | 'right' | 'rear';
  faceB: 'front' | 'left' | 'right' | 'rear';
  // 접촉점은 양쪽 구획의 현재 외곽으로 계산한다.
};

type RevealEvent = {
  id: string;
  sourceEventIds: string[];
  sourceBattleId?: string;
  commanderId: string;
  contactId?: string;
  atMs: number;
  kind: 'combatLoss' | 'reinforcement' | 'recovery'
      | 'desertion' | 'reorganization' | 'death';
  // Convert to the existing legal integer quantum before allocation.
  amountQuanta: number;
};
```

필요한 책임은 다음과 같다.

1. 원본 기록 정규화: 실제 참여자, 교전 관계, 병력 변화, 종료 상태를 읽는다.
2. 배치: 병력과 공간 예산으로 구획과 초기 위치를 만든다.
3. 전술 선택: 조건이 성립하는 주전술, 상대 대응, 전환을 고른다.
4. 경로 생성: 이동, 회전, 접촉, 퇴장 경로를 만든다.
5. 손실 연결: 실제 손실을 해당 교전의 접촉 구간에 배정한다.
6. 임의 시각 평가: 같은 plan과 같은 t에서 항상 같은 화면 상태를 만든다.
7. 렌더링: 위치와 접촉을 그린다. 피해를 계산하거나 난수를 소비하지 않는다.

원본 기록의 ID가 숫자라면 숫자를 유지해도 된다. 지휘관의 slot만으로 동일인을 식별하지 말고 원본 인물 ID 또는 소속, 역할, slot, generation을 포함한 안정적인 키를 사용해라.

공격국과 방어국이라는 원본 소속과, 현재 장면에서 전진하는 쪽과 버티는 쪽을 구분해라. 방어국이 반격하면 그 소속과 원본 기록은 유지하면서 전진 행동을 사용할 수 있어야 한다. 우회 행동을 원래 공격국에게만 하드코딩하지 마라. 국왕이라는 이유만으로 승리와 무관하게 항상 원위치로 후퇴시키는 현재 정책도 실제 기록과 역할에 맞춰 검토해라.

원본 참여자나 종료 상태를 찾지 못했다고 병력 0, 전사, 패배로 기본 처리하지 마라. 식별 오류를 먼저 해결하고 그래도 미확정인 경우 개발 검증에서 해당 계획을 실패로 보고해야 한다. 무승부와 자동 진입은 승패의 단순 참거짓 분기와 분리해라.

## 6 접촉 공간과 이동의 공통 규칙

### 6.1 접촉 위치를 실제로 맞춰라

- 병력 구획마다 중심, 진행 방향, 폭과 깊이를 보유해라.
- 접촉 여부는 중심 간 고정 거리만으로 판단하지 말고 구획의 외곽과 접촉 방향을 사용해라.
- 시각적 공격 거리 허용치는 상수로 분리해라. 그림이 닿지 않는 긴 공간에 칼 효과를 띄우지 마라.
- 측면 공격은 해당 구획의 왼쪽이나 오른쪽 외곽에 도착해야 한다. 중앙 앞까지 직진한 뒤 측면 공격 문구를 띄우지 마라.
- 후방 공격도 실제로 뒤쪽에 접근한 경로가 있어야 한다.
- 효과는 두 구획 중심의 단순 중간점이 아니라 실제 접촉 면에 표시해라.
- 공격 방향에 맞춰 병사와 구획의 방향을 자연스럽게 바꿔라. 회전과 이동은 순간이동 없이 보간해라.

### 6.2 한 점에 모든 부대가 겹치지 않게 해라

작은 부대 외곽의 길이만큼 동시에 접촉할 수 있는 공간이 존재한다. 접촉 슬롯이나 가벼운 예약 방식으로 앞, 좌우, 후방의 수용량을 관리해라. 시작값으로 작은 구획 하나에 직접 붙는 상대 구획은 정면과 양측면 등 2~3개 안팎으로 제한할 수 있다. 정확한 값은 구획의 실제 폭에 따라 결정해라.

접촉할 자리가 없으면 후속 구획은 대기하거나 빈 접근로를 찾는다. 15개 부대가 작은 부대 중심으로 동시에 포개지면 실패다. 대기 부대는 전방을 바라보며 대열을 유지하고 그 부대에 허위 피격 효과를 붙이지 마라.

원래 실제 교전을 하지 않은 지휘관은 전술화면 안의 후방 대기나 준비 이동까지만 허용하고 combatLoss를 배정하지 마라. 같은 지휘관의 여러 구획 사이에서도 동일 손실 사건을 중복 배정하지 마라.

### 6.3 새로운 물리 엔진은 필요 없다

구획 크기, 경로 통로, 접촉 슬롯, 간단한 겹침 회피로 구현해라. 병사 개인마다 길찾기와 전투 판정을 만드는 것은 범위 밖이다. Canvas 병사들은 구획 중심과 형태를 따라 움직이는 시각적 구성원으로 처리해라.

가로로 퍼짐, 밀집, 깊은 대열, 쐐기, 전선이 휘어지는 형태를 구획 위치와 내부 병사 배치로 표현해라. 현재의 가로 4명 고정 직사각형만으로 모든 장면을 처리하지 마라.

## 7 싸우는 모습과 손실을 하나로 연결하는 규칙

### 7.1 손실 장부를 먼저 만들어라

각 실제 교전의 손실을 피해 지휘관별로 정규화하고 출처 ID를 유지해라. 이전 교전 후 남은 병력이 다음 교전의 시작 병력이 되는 관계를 보존해라. 최종 병력 차이 하나를 모두 전투 피해로 취급하지 마라.

계산은 기존 병력 단위에 해당하는 정수 quantum으로 해라. 만 명 단위 규칙이면 1 quantum은 1만이다. 다른 기존 규칙이 설정되면 그 규칙의 최소 단위로 환산해라. 부동소수 누적으로 손실 총합이 달라지지 않게 해라.

지휘관별로 다음 등식이 성립해야 한다.

`최종 병력 = 시작 병력 + 기록된 증가분 - 기록된 감소분`

증가분과 감소분에는 전투 외 변화도 실제 기록에 따라 구분한다. 기록을 읽어도 분류를 확정할 수 없는 변화는 전투 타격으로 꾸미지 말고 별도 상태 정리 사건으로 보존하고 검증 로그에 남겨라. 분류 불명 변경 때문에 최종 값을 몰래 맞추지 마라.

### 7.2 접촉 구간을 만든 뒤 손실을 배정해라

원본 교전 A 대 B의 손실은 해당 실제 지휘관 A와 B 소속 구획의 접촉 구간에 연결해라. 가까운 다른 지휘관으로 대체하지 마라. 같은 소속 구획들 중 어느 구획이 해당 교전을 표현할지는 연출기가 선택할 수 있다.

접촉 구간에는 다음을 함께 배정해라.

- 공격 또는 압박 동작.
- 방어, 피격, 밀림 등의 반응.
- 접촉 면의 타격 효과.
- 해당 지휘관의 병력 감소와 막대, 병사 그림 감소.
- 이후의 버팀, 재정렬, 후퇴 또는 돌파 동작.

공격 및 피격 애니메이션의 타격 프레임을 확인하고 손실 공개 시각과 연결해라. 초기 허용 오차 목표는 타격 효과와 숫자 감소 사이 약 150ms 이내다. 사용 중인 이미지 프레임 길이가 다르면 수치를 조정하고 검증 결과에 실제 기준을 써라.

손실은 이동 도중 아무 시각에나 나오면 안 된다. 실제 접촉 계획이 불가능하면 계획을 재조정하거나 더 단순한 정면 교전으로 대체해라. 없는 접촉을 선언해 검사를 통과시키지 마라.

### 7.3 분할 횟수는 실제 손실 크기에 맞춰라

고정 다섯 번 분할을 없애라. 0이면 감소 사건이 0개다. 손실이 1 quantum이면 감소 사건은 최대 1개다. 큰 손실은 접촉 구간 길이와 주요 교전 순간에 맞춰 여러 번 나누어 공개해라. 각 사건의 양은 양의 정수 quantum이고 합계는 원래 손실과 정확히 같아야 한다.

예시는 다음과 같다. 이 예시는 표시 정책이며 게임 피해 공식을 새로 정의하지 않는다.

| 실제 기록 | 허용되는 연출 예시 |
| --- | --- |
| 5만에서 3만 | 접촉 중 1만 감소 두 번 |
| 30만에서 18만 | 3만, 2만, 4만, 3만 등으로 분할하되 원본 교전별 장부와 순서를 보존 |
| 1만에서 1만 | 숫자 유지, 방어와 흔들림으로 긴장 표현 |
| 1만에서 0만 | 결정적인 접촉 또는 실제 종료 사건에 1만 감소 한 번 |

손실 없는 공격 동작은 막힘, 무기 교환, 압박으로 보여줘도 된다. 모든 칼질마다 숫자를 줄이지 마라. 숫자는 원래 최소 단위를 유지하며 부드러운 막대 보간으로 가짜 소수점 병력을 표시하지 마라.

### 7.4 전사와 병력 소진은 다른 사건이다

병력 0이 곧 지휘관 전사를 뜻하지 않는다. 실제 사망 사건이 있는 사람만 전사 표시를 해라. 사망 시각 이후 동일 인물의 공격, 명령, 증원, 재등장 트랙이 남지 않게 해라. 같은 slot에 새 인물이 들어온 경우 generation 또는 실제 인물 ID로 구별해라.

시체나 퇴장 효과는 허용하지만 실제 생사와 병력 수는 원본 종료 상태에 정확히 맞아야 한다.

## 8 전술 공통 실행 계약

각 전술은 다음 항목을 가진 독립적인 행동 구성으로 구현해라.

1. 적용 조건과 제외 조건.
2. 참여 구획과 예비 구획의 배정.
3. 시작 형태와 목표 형태.
4. 단계별 경로, 진행 방향, 접촉 면.
5. 상대의 대응 움직임.
6. 손실 공개에 사용할 접촉 구간.
7. 성공, 저지, 중단 시의 다음 행동.
8. 공간이 모자라거나 참여자가 사라질 때의 대체 행동.
9. 이 전술을 다른 전술과 구별하는 검증 지표.

통상 각 전개 구간 안에서 주전술, 상대 대응, 필요 시 전환 전술 하나로 구성해라. 한 집단군 묶음 전체를 전술 두 개만으로 끝내라는 의미가 아니다. 다음 실제 교전이나 반격 구간으로 넘어가면 새 조합을 이어서 사용할 수 있다. 최대 숫자를 맞추기 위해 불필요한 전술을 붙이지 마라. 전술 단계는 이전 단계의 상태를 받아야 한다. 돌파 전에 돌출부 확대, 접촉 전에 반격, 살아 있는 집단 하나에 분리된 철수를 적용하면 안 된다.

전술 간 공통 이동 함수는 재사용해도 된다. 그러나 이름과 문구만 다르고 좌표 트랙, 접촉 면, 전열 변화가 같으면 서로 다른 전술로 인정하지 않는다.

전술 선택의 우선순위는 `원본 사건과 결과의 일관성 > 배치와 접촉의 성립 > 장면 가독성 > 시각적 다양성`이다. 이미 확정된 결과와 충돌하면 멋있는 전술을 포기하고 성립하는 행동으로 바꿔라.

## 9 전술별 상세 구현 규칙

### T01 중앙 집중 돌파 center break

- 조건: 중앙에 집중할 병력과 상대 전열이 있고, 실제 승리 및 진격 기록이 돌파 성공 표현을 허용한다. 성공 근거가 없으면 저지되는 시도로만 표현한다.
- 배치: 중앙 공격 구획의 간격을 줄이고 깊이를 늘린다. 양익은 상대 부대를 붙잡거나 현재 전선을 유지한다.
- 경로: 중앙 구획들이 하나의 좁은 접촉 구역으로 모인다. 여러 구획이 같은 점에 겹치지 않도록 앞뒤 순서를 둔다.
- 대응: 상대 중앙은 밀리거나, 후방 구획이 틈을 메운다. 무조건 중앙을 뚫지 마라.
- 손실: 중앙 정면 접촉에서 공개한다. 돌파가 성공하기 전부터 적 후방에서 피해 효과를 띄우지 마라.
- 종료: 성공하면 뒤쪽 공간으로 진입하고 T06으로 연결할 수 있다. 저지되면 정면 교착 또는 공격 방향 전환.
- 식별 기준: 중앙 전선의 국지적 돌출, 좁은 돌파구, 양익보다 앞선 중앙이 보여야 한다.

### T02 편익 집중 공세 wing focus

- 조건: 한쪽에 병력을 보탤 공간과 실제 교전 참여 병력이 있다.
- 배치: 한쪽 날개의 전열 폭 또는 대열 깊이가 커진다. 반대 날개는 적게 움직인다.
- 경로: 후방 구획이 선택한 날개의 뒤로 이동한 뒤 함께 정면 진격한다. 적 바깥을 크게 돌아 후방으로 가지 않는다.
- 대응: 상대는 해당 날개 쪽으로 지원을 보내거나 그 날개를 뒤로 접는다.
- 손실: 강화된 날개의 정면 접촉에 연결한다.
- 종료: 한쪽만 먼저 전진하는 비대칭 전선 또는 공세 저지.
- 식별 기준: 한쪽 병력 집중과 정면 돌출이 보여야 한다. T05의 외곽 우회 궤적과 달라야 한다.

### T03 사선 진격 oblique

- 조건: 최소 세 개 안팎의 전선 구획을 서로 다른 시각에 접촉시킬 수 있다.
- 배치: 선택한 날개, 중앙, 반대 날개 순으로 전후 위치가 엇갈린다.
- 경로: 선두 날개가 먼저 전진하고 나머지가 순차적으로 전진한다. 주요 접촉 시차는 기본 속도에서 식별 가능해야 한다. 초기 목표는 구간별 약 0.7~1.2초다.
- 대응: 상대 전열이 비스듬히 접히거나 구간별로 방향을 조정한다.
- 손실: 해당 구획이 접촉한 뒤 순차적으로 공개한다. 아직 도착하지 않은 반대 날개에 전투 피해를 공개하지 마라.
- 종료: 사선 전선에서 전면 교전으로 이어지거나 먼저 접촉한 쪽이 저지된다.
- 식별 기준: 날개에서 반대 날개로 이어지는 접촉 시차와 계단형 또는 기울어진 전선.

### T04 양익 협공 pincer

- 조건: 중앙을 유지할 집단과 양쪽으로 움직일 집단, 양쪽 접근 통로가 있다. 작은 병력 하나를 세 군대로 복제해 만들지 마라.
- 배치: 중앙은 접촉을 유지하고 좌우 날개는 외곽에 분리 배치한다.
- 경로: 양익이 서로 반대 방향으로 바깥에 벌어졌다가 안쪽으로 회전해 적의 양측면에 접근한다. 좌우가 정확히 같은 시각에 움직일 필요는 없다.
- 대응: 상대 양끝이 바깥쪽으로 회전하거나 전선을 좁혀 방어한다. 포위 저지가 필요하면 한쪽 통로를 막을 수 있다.
- 손실: 중앙 접촉과 양측면 접촉을 각각 연결한다. 도착하기 전 측면 피해는 금지.
- 종료: 결과가 허용하면 압박 범위가 좁아진다. 생존 병력이 후퇴해야 한다면 탈출 공간을 남겨라. 전멸이나 포로 처리를 새로 만들지 마라.
- 식별 기준: 중앙 고정과 양쪽 외곽 경로, 두 측면의 접촉.

### T05 편익 포위 hook

- 조건: 정면 유지 병력과 별도 우회 병력, 한쪽 외곽 통로가 있다.
- 배치: 중앙과 반대쪽 날개가 전열을 유지하고 선택한 날개만 분리한다.
- 경로: 선택한 날개가 적 전열 바깥을 지나 옆이나 뒤로 진입한다. 우회 경로의 외곽 변위는 T02의 단순 보강보다 분명히 커야 한다.
- 대응: 상대의 가까운 외곽 구획 또는 예비대가 회전해 차단한다.
- 손실: 우회가 실제 도착하고 접촉한 뒤 해당 측면 또는 후방에서 공개한다.
- 종료: 성공하면 편측 압박, 저지되면 측면 별도 교전, 실패하면 원전선 복귀 또는 후퇴.
- 식별 기준: 한쪽만 크게 도는 궤적. 양쪽이 돌면 T04와 구분되지 않으므로 금지.

### T06 돌출부 확대 breach

- 조건: 이전 단계에서 적 전열 뒤로 통과할 수 있는 돌파구가 실제 연출 상태에 존재해야 한다.
- 배치: 돌파구 앞과 뒤에 후속 구획을 배치한다.
- 경로: 좁은 통로를 통과한 뒤 적 전열 뒤쪽에서 좌우로 갈라져 통로 양옆을 압박한다. 통과 전부터 좌우로 순간이동하지 마라.
- 대응: 상대는 양옆 부대를 안쪽으로 돌리거나 뒤쪽으로 물러나 새 전열을 만든다.
- 손실: 통로 입구 접촉과 통과 이후의 안쪽 측면 접촉을 구별한다.
- 종료: 돌파구 폭이 넓어지거나 새 전열에 막힌다.
- 식별 기준: 통로 진입 후 분기와 접촉 폭 확대. T01의 전방으로 찌르는 동작과 달라야 한다.

### T07 파상 공세 waves

- 조건: 실제 교전에 참여하는 전방 대열과 후속 대열을 구분할 수 있다.
- 배치: 전방, 후속 대열을 명확하게 분리한다.
- 경로: 1차 대열이 교전한 뒤 물러나거나 옆으로 비켜 공간을 내주고, 2차 대열이 같은 전선을 이어받는다. 단순히 후방 부대가 처음부터 늦게 출발하는 것으로 끝내지 마라.
- 대응: 방어자는 같은 전선을 지키거나 차례로 밀린다.
- 손실: 실제 기록에 맞춰 각 대열의 접촉 구간에 공개한다. 대기 대열에는 타격 효과를 붙이지 마라.
- 종료: 다음 대열의 압박으로 이어지거나 마지막 공세가 멈춘다.
- 식별 기준: 같은 접촉 구역에서 전방 담당 구획이 교체되어야 한다.

### T08 집중 압박 pressure

- 조건: 유지 가능한 접촉선과 실제 교전 관계가 있다. 비교적 넓게 사용할 수 있는 기본 전술이다.
- 배치: 교대 없이 전열의 연속성을 유지한다.
- 경로: 기존 구획들이 짧은 전진과 멈춤을 반복한다. 대군이더라도 접촉하지 못한 후방은 정렬을 유지한다.
- 대응: 상대는 버티거나 같은 방향으로 조금씩 물러난다.
- 손실: 여러 접촉 지점에 분산하되 실제 손실이 있는 지휘관에게만 공개한다.
- 종료: 전체 전선의 완만한 이동, 교착 또는 공격 중단.
- 식별 기준: T07과 달리 전방 대열이 교체되지 않는다. T01과 달리 좁은 중앙 돌파구를 만들지 않는다.

### T09 후속대 투입 reserves

- 조건: 후방에 실제 교전 가능한 병력 구획이 남아 있어야 한다. 비전투 지휘관을 전투 참여자로 새로 만들지 마라.
- 배치: 예비대가 전방과 떨어진 위치에서 대기한다.
- 계기: 특정 구간의 밀림, 전열 틈 또는 기존 접촉면의 부족 상태를 먼저 보여준다.
- 경로: 그 구간으로만 예비대가 이동해 접촉선에 합류한다. 전선 전체를 일괄 전진시키지 마라.
- 대응과 손실: 합류한 구획과 그 실제 상대의 접촉 뒤에 손실을 공개한다. 합류 전 병력 숫자를 새로 증가시키지 마라. 원래 보유 병력의 이동은 증원이 아니다.
- 종료: 틈이 메워지거나 보강 뒤에도 밀린다.
- 식별 기준: 대기, 특정 공백의 발생, 표적 이동, 합류라는 네 단계.

### T10 전선 유지 hold

- 조건: 실제로 버티는 구간을 표현할 수 있다. 최종 패배 전의 저항 구간에도 사용할 수 있다.
- 배치: 비교적 연속적인 방어선과 정해진 기준선을 둔다.
- 경로: 큰 이동 대신 짧은 밀림과 재정렬을 한다. 공격이 올 때는 해당 접촉 방향을 향해 대응한다.
- 손실: 같은 전선의 실제 접촉에서 공개한다. 손실 0이면 숫자를 유지한다.
- 종료: 방어 성공, 짧은 역습 전환 또는 기록상 패배에 따른 철수.
- 식별 기준: 기준선 주변에서 유지되는 방어선. 화면 전체가 계속 후퇴하면 T13과 구분되지 않으므로 금지.

### T11 국지 역습 local counter

- 조건: 실제 승리한 방어 구간 등 되받아칠 근거가 있고 가까운 대응 병력이 있다.
- 배치: 한 구간만 먼저 밀린 상태를 만든다.
- 경로: 그 구간의 인접 구획 또는 예비대가 짧게 앞으로 튀어나가 상대를 물린 뒤 원래 전선 부근에서 멈춘다.
- 대응: 상대는 짧게 물러나 재정렬하거나 해당 접촉을 종료한다.
- 손실: 밀린 과정과 되받는 과정의 실제 장부를 구분해 연결한다.
- 종료: 국지적 전선 복구. 실제 반격 진격 기록이 없으면 적 진영 깊숙이 추격하지 마라.
- 식별 기준: 일부 구간만 후퇴, 짧은 재전진, 원래 기준선 부근 정지.

### T12 반격 돌파 counter break

- 조건: 실제 반격 또는 반격에 따른 진격, 영토 획득 기록이 있어야 한다. 일반 방어 성공만으로 자동 선택하지 마라.
- 배치: 이전 공격의 접촉선과 공격 중단을 먼저 보여준다.
- 경로: 방어 측 여러 구획이 전진으로 전환해 이전 접촉선 너머로 진입한다. 원래 공격 측은 뒤로 물러나거나 새 방어선을 만든다.
- 손실: 전진한 반격 부대와 물러나는 실제 상대의 접촉에 연결한다.
- 종료: 결과가 허용하는 범위에서 전진, 뒤이어 실제 지도 점령 장면으로 연결.
- 식별 기준: 공격 주도권이 바뀌고 이전 기준선을 넘어선다. T11처럼 제자리 복구로 끝나면 안 된다.

### T13 단계적 후퇴 staged retreat

- 조건: 후퇴해야 할 생존 병력이 있고 서로 엄호할 수 있는 집단이나 대열이 있다.
- 배치: 일부는 접촉을 유지하고 일부는 후방에 새 전열을 만든다.
- 경로: 후방으로 빠진 대열이 정렬한 뒤 기존 엄호 대열이 접촉을 끊고 합류한다. 가능하면 두 단계 이상으로 보여준다.
- 대응: 상대는 빈 공간만큼 전진하되 끝없이 추격하지 않는다.
- 손실: 접촉 중인 엄호 집단이나 실제로 추격에 잡힌 집단에만 공개한다.
- 종료: 서로 연결된 형태의 후퇴, 실제 지도 후퇴와 연결.
- 식별 기준: 접촉 담당과 이동 담당이 번갈아 바뀐다. 전 부대가 같은 시각 같은 거리만큼 후진하면 구현 실패다.

### T14 분리된 철수 split retreat

- 조건: 분리해서 철수할 생존 집단이 둘 이상 있고 원본 결과와 충돌하지 않는다.
- 배치: 중앙의 연결이 약해지거나 구획 사이 거리가 벌어지는 상태를 만든다.
- 경로: 각 집단이 서로 다른 안전 방향으로 이동하고 접촉을 끊는다. 화면의 서로 다른 탈출 통로를 사용하되 실제 지도 후퇴 목적지는 원본을 유지한다.
- 대응: 상대는 일부를 압박하거나 전진을 멈춘다. 없는 추격 피해를 만들지 마라.
- 손실: 실제로 접촉이 남아 있는 집단에만 연결한다.
- 종료: 여러 집단이 따로 이탈. 최종 장수 생사와 잔존 병력은 원본과 일치.
- 식별 기준: 퇴장 방향과 집단 간 거리가 분리된다. T13의 연결된 엄호 후퇴와 달라야 한다.

## 10 공격과 상대 대응을 함께 계획해라

각 공격 전술은 상대의 대응 트랙까지 함께 생성해야 한다. 상대가 우회를 실시간 탐지하는 복잡한 AI를 만들 필요는 없다. 확정된 결과를 알고 있는 연출 계획기가 양쪽 경로를 같이 만들면 된다.

| 공격 행동 | 저지되는 경우의 대응 | 성공하는 경우의 대응 |
| --- | --- | --- |
| 중앙 돌파 | 예비대가 중앙을 메우고 공격 정지 | 중앙이 밀리고 뒤로 새 전열 형성 |
| 편익 집중 | 해당 날개 보강 | 그 날개가 뒤로 접힘 |
| 양익 협공 | 양끝 회전 또는 한쪽 통로 차단 | 양측면 압박 속에서 전선 축소 |
| 편익 포위 | 외곽 구획이 돌아서 차단 | 차단 구획이 밀리며 측면 접촉 |
| 돌출부 확대 | 돌파구 양옆이 안쪽으로 회전 | 양옆 구획이 분리되며 후퇴 |
| 반격 돌파 | 이전 공격군이 새 방어선 형성 | 이전 공격군이 접촉을 끊고 철수 |

실패와 성공은 새 확률 판정으로 결정하지 않는다. 원래 교전과 종료 상태를 읽고 허용되는 해석을 선택한다. 최종 승자가 모든 국지 장면에서 이겨야 하는 것은 아니지만 실제 지휘관의 승패와 손실을 반대로 보여주지는 마라.

같은 장면 안에서 공격 측과 방어 측의 경로가 서로 다른 전술을 주장하며 충돌하지 않게 중앙 계획기에서 조정해라. 좌표 공간, 접촉 예약, 시각을 공유해야 한다.

## 11 병력과 지휘관 수가 불균형한 실제 적용 예시

아래는 개발용 가상 fixture의 조건과 기대 표현이다. 실제 플레이 결과를 조작하라는 지시가 아니다. 해당 승패가 기존 규칙상 생성될 수 없다면 재생 계층용 기록 fixture로 구분하고, 실제 시뮬레이션에서 나온 결과라고 주장하지 마라.

### 사례 A 5지휘관 총 5만 대 3지휘관 총 30만

작은 쪽은 각 1만, 큰 쪽은 각 10만으로 구성한 fixture를 사용해라.

큰 쪽이 승리한 기록에서는 다음 흐름이 가능해야 한다.

1. 작은 꾸러미 다섯 개와 두꺼운 대열 세 집단이 처음부터 구별된다.
2. 실제 원본 교전 관계에 맞춰 정면 접촉한다. 5대3을 억지로 1대1 대결 다섯 개로 만들지 않는다.
3. 집중 압박 중 접촉한 지휘관에게만 실제 손실을 공개한다.
4. 별도 병력 구획이 한쪽으로 우회하고 상대 끝 부대가 방향을 틀어 차단한다.
5. 기록상 패배하는 구간이 밀리며 추가 손실을 공개한다.
6. 작은 쪽이 단계적으로 철수하고 큰 쪽은 결과가 허용하는 만큼 전진한다.

작은 쪽이 승리한 반대 fixture도 만들어라. 큰 쪽의 규모는 유지하고 전선 유지, 공격 저지, 공격군 철수로 표현한다. 실제 역공 기록이 있을 때만 작은 쪽이 전진한다. 다수가 패배했다는 이유로 다수 병력을 모두 0으로 만들지 마라.

### 사례 B 15지휘관 총 60만 대 1지휘관 총 1만

큰 쪽은 각 4만, 작은 쪽은 1만으로 구성해라.

큰 쪽 승리에서는 다음을 확인해라.

- 15개 지휘관 부대는 전방과 후속 대열로 배치되고, 작은 쪽은 작은 꾸러미 하나다.
- 접촉 공간을 실제로 차지할 수 있는 일부 구획만 직접 붙는다.
- 나머지는 대기하거나 외곽으로 이동하고 같은 점에 겹치지 않는다.
- 원본 기록에 실제 참여하지 않은 지휘관의 피해와 공격을 만들지 않는다.
- 작은 쪽의 병력 소진, 생존 후퇴 또는 전사를 원본 상태에 따라 구별한다.

작은 쪽 방어 성공에서는 다음을 확인해라.

- 큰 쪽의 실제 교전 부대들이 접촉하고 손실을 공개한 뒤 물러난다.
- 같은 작은 부대를 여러 복제본으로 만들어 각각의 적과 싸우게 하지 않는다.
- 방어자는 계속 같은 인물과 같은 병력 장부를 사용한다.
- 1만에서 1만인 경우 병력 숫자를 줄이지 않는다.
- 60만의 공세 실패가 60만 전멸처럼 보이지 않는다. 실제 잔존 병력을 유지한다.
- 한쪽 지휘관이 1명이라는 이유만으로 무조건 6초에 끝내지 않는다.

### 사례 C 1지휘관 총 60만 대 15지휘관 총 15만

대군 지휘관 한 명의 병력을 여러 시각적 구획과 대열로 표현해라. 같은 사람을 여러 지휘관으로 복제하지 마라. 상대의 지휘관이 15명이라고 더 많은 병력을 가진 것처럼 그리지 마라. 지휘관 수를 새로운 포위 보너스나 공격력으로 사용하지 마라.

### 사례 D 같은 총병력과 서로 다른 지휘관 수

1명 30만 대 10명 30만, 3명 30만 대 15명 30만 등을 확인해라. 총 그림 수와 점유 규모는 비슷해야 하고, 소속 구획과 이름표만 달라져야 한다. 지휘관이 많다는 이유로 병사 그림 수가 폭증하면 실패다.

### 사례 E 소수 손실과 손실 없는 교전

1만에서 1만, 1만에서 0만, 2만에서 1만 fixture를 따로 사용해라. 허용 최소 단위보다 작은 숫자 표시, 0 피해 팝업 반복, 죽은 뒤 재공격, 병력의 음수화가 없어야 한다.

## 12 재생 시간과 읽을 수 있는 전투 흐름

시간을 단순 배수로 늘려 기존 6초, 16초, 18초 동작을 느리게 재생하지 마라. 반복 칼질과 정지 대기로 시간을 채우지 마라. 실제 교전 기록마다 접근, 접촉, 손실, 승패, 결과 반응, 점령 또는 다음 방어라는 흐름을 배정하고 이를 한 전장 안에서 연결해라.

사용자가 확정한 기본 속도 1배속 기준은 일반 집단군 30~45초, 진격과 반격 및 점령 변화가 복잡한 묶음 60~90초다. 사건이 매우 많으면 예외적으로 90~120초까지 허용할 수 있지만 필수 사건의 읽기 시간을 우선 계산해라. 단순하고 일방적인 짧은 기록은 15~25초 안팎으로 끝내도 된다. 길이를 맞추려고 가짜 교전이나 불필요한 정지 구간을 추가하지 마라. 확정 기준과 예외는 25절에서도 정리한다.

지휘관 수가 적다는 이유만으로 6초로 줄이지 마라. 1명이 15명을 막아내는 기록이면 여러 저지와 승리, 공격군 교대가 충분히 드러나야 한다. 다만 실제 기록이 두 교전뿐이면 열 번 싸운 것처럼 가짜 결과를 만들지 마라.

현재 교전 결과는 대체로 2~3초 이상, 점령과 재탈환, 전사 같은 중요 결과는 3~4초 안팎으로 읽을 수 있게 배정해라. 긴 이름과 영토명이 있으면 문자 수에 맞춰 조정한다. 새로운 중요 결과로 기존 문구를 읽기도 전에 덮지 말고, 그동안 전장의 다른 부대는 대기, 정렬, 독립 교전을 계속할 수 있게 한다.

짧은 부대 이름표 결과와 상단 현재 결과는 같은 원본 사건 ID에 연결해라. 동시에 너무 많은 승패 문구를 띄우지 마라. 기본은 주요 결과 하나와 보조 결과 최대 하나다. 큰 결과가 연속되면 전장 전체를 초기화하지 말고 읽기 순서를 갖는 대기열을 사용한다.

중요 사건마다 1.6초 고정 정지를 계속 더해 전투가 멈춰 서게 하지 마라. 가능한 사건은 움직이는 전장 위 강조로 처리하고 진짜 강조가 필요한 사건만 기존 mass 전용 정지 구간에 연결해라. 같은 사건을 전술 본편 안에서 두 번 처리하지 않는다. 전술 종료 뒤 기존 지도 공개와 후퇴 및 점령 순서는 바꾸지 않는다.

기존 배속은 존중한다. 이 과업 때문에 4배속이나 8배속을 강제로 1배속으로 바꾸거나 전역 중요 장면 정책을 수정하지 마라. 이 문서의 읽기 시간 목표는 기본 속도 기준이다. 빠른 재생에서도 정보 순서와 최종 장부는 같아야 하며 표시가 밀려 화면 밖까지 대기열이 쌓이면 안 된다.

전술 화면 한 묶음의 시간은 내부 사건 수와 읽기 예산으로 정하고 상위 전체 턴 시간을 직접 재설계하지 마라. 반복 전투가 길어져 영상 편집에 미치는 영향은 검증 결과에 적되 다른 모드의 시간을 자동으로 줄여 상쇄하지 마라.

## 13 재생 제어와 결정성

같은 계획의 같은 시각을 평가하면 같은 위치, 병력, 생사, 전술 단계가 나와야 한다. 위치 평가 함수와 손실 평가는 렌더링 횟수에 영향을 받으면 안 된다.

- 일시정지 중 병력이 감소하거나 이동하면 안 된다.
- 재개하면 이어서 재생되어야 한다.
- 배속 변경으로 손실이 중복 공개되거나 건너뛰어 종료 값이 어긋나면 안 된다.
- 되감기와 다시 보기는 초기 연출 상태에서 재현되어야 한다.
- 건너뛰기는 최종 상태에 정확히 도달해야 한다.
- 기존 재생기가 임의 시점 이동을 지원하면 해당 시점 이전 사건을 누적해 같은 상태를 계산해야 한다. 미지원 기능을 추가하기 위해 공용 재생기를 확장하지 말고 전술 계층의 순수 평가 테스트로 확인해라.
- 오디오의 일회성 사건은 별도 ID 장부로 관리해 재렌더링이나 일시정지 때 중복 재생하지 마라.
- 전투 계획 생성 중 게임 난수 함수를 호출하지 마라.

기존 재생 시계와 RAF를 재사용해라. 부대마다 setInterval이나 독립 타이머를 만들지 마라. 렌더 루프에서 경로 탐색과 전체 계획 생성을 반복하지 마라.

## 14 이름표와 화면 가독성

지휘관 15명 이상도 처리해라. 이름표를 모두 같은 점에 겹치게 배치하면 안 된다. 기존 이름표의 정체성은 유지하되 실제로 교전하거나 중요한 사건이 있는 부대를 우선 눈에 띄게 하고, 다른 부대의 표시는 충돌을 회피해라.

병사 구획이 이동하거나 좌우로 갈라져도 같은 지휘관의 이름과 병력 장부가 어디에 연결되는지 알아볼 수 있어야 한다. 수치 팝업이 같은 지휘관의 여러 구획에서 중복 표시되지 않게 해라. 총병력 표시는 그 시각의 지휘관 장부 합계와 정확히 같아야 한다.

기본 전술은 명령 문구를 읽지 않아도 다음을 알아볼 수 있어야 한다.

- 어느 쪽이 병력이 많은가.
- 어디가 먼저 맞붙었는가.
- 어느 전선이 밀리는가.
- 어떤 부대가 우회하거나 보강하는가.
- 누가 후퇴하고 누가 남아 있는가.

## 15 성능과 렌더링 범위

기존 Canvas와 병사 프레임 캐시를 우선 활용해라. 병사마다 DOM 노드를 만들지 마라. 이동 계획은 부대와 구획 단위로 계산하고 병사 위치는 구획의 로컬 배치에서 파생해라.

접촉 탐색은 연출 계획 단계에서 대부분 해결하고, 프레임마다 모든 병사 쌍을 비교하지 마라. 깊이 정렬, 국가색 처리, 기존 그림자와 고해상도 대응을 유지해라. 화면 크기 변경 시 최종 상태나 기록이 바뀌면 안 된다.

초기 성능 목표는 일반 데스크톱에서 기본 속도 재생이 눈에 띄게 끊기지 않는 수준이다. 가능하면 30fps 이상을 측정하고 테스트 환경, 실제 측정 범위와 최저치를 적어라. 측정하지 않은 성능을 달성했다고 보고하지 마라. 병사 그림 예산은 성능 검증으로 낮출 수 있지만 전술의 서로 다른 경로와 병력 대소 관계는 유지해라.

## 16 구현 순서

1. 61번 원본을 보존하고 해시와 기존 실행 경로를 확보한다. 전술화면 허용 범위와 변경 금지 모듈 목록을 만든다.
2. 기존 결과 보존 기준, 전술화면 앞뒤의 지도 장면 목록과 공개 장부 스냅샷을 확보한다.
3. 기존 집단군 묶음 안의 개별 교전, 손실, 실제 이동과 소유권 전환 사건을 읽는 전술 전용 어댑터를 만든다.
4. BattleBeat와 읽기 전용 TerritoryTransition 장부를 만들어 점령 후 재탈환과 중간 승패가 빠지지 않는지 먼저 검사한다.
5. 공통 병력 축척과 시각적 구획, 접촉 공간을 구현한다.
6. T08 집중 압박과 T10 전선 유지를 사용해 여러 실제 교전이 하나의 화면 안에서 끊김 없이 이어지고 손실과 결과가 맞는 최소 흐름을 완성한다.
7. 14개 전술과 상대 대응을 각각 구현하고 전개 구간마다 연결한다.
8. 상단 현재 교전, 부대별 승패 표시, 작은 영토 상태줄을 연결한다. 최종 결과를 미리 노출하지 않는다.
9. 전사와 종료 요약, 기존 재생 시계와 접촉 효과음을 연결한다. 지도 복귀와 지도 장부는 원본 동작을 유지한다.
10. 극단 사례와 점령 및 재탈환, 같은 지휘관 연승 후 패배를 개발 fixture에서 검증한다.
11. 실제 자동 선택 전투와 1배속, 4배속, 8배속, 일시정지와 다시 보기를 확인한다.
12. 변경 모듈 diff와 원본 시뮬레이션, 전술화면 외 장면의 동일성을 검사한다.
13. 최종 단일 HTML을 다시 묶고 그 파일을 브라우저에서 직접 확인한다.

다른 시스템을 리팩터링해야 더 깔끔하다는 이유로 범위를 넓히지 마라. 전술화면 전용 어댑터와 내부 상태를 사용하고 공용 코드에 불가피한 연결 변경이 있다면 변경 이유와 비전술 경로가 동일함을 별도로 증명해라.

## 17 검증 시나리오

### 17.1 전술별 시연

개발용 fixture 또는 내부 미리보기에서 각 전술을 강제로 선택해 볼 수 있게 해라. 이 도구는 실제 플레이 기록을 수정하지 않아야 하며 일반 사용자 흐름에 규칙 설명 패널을 추가하는 방식으로 만들지 마라. 기본 게임 UI에 노출하지 않는 별도 개발 페이지나 테스트 진입점이 좋다.

각 전술에 적합한 fixture를 사용하고 다음을 확인해라.

- 전술 이름과 명령 문구를 가려도 해당 움직임의 차이가 보인다.
- 전술의 적용 조건이 실제로 성립한다.
- 적절한 상대 대응과 접촉 면이 있다.
- 손실은 접촉 후 타격 장면에서 공개된다.
- 종료 상태가 실제 기록과 맞는다.

14개 전술에 모두 같은 기록을 억지로 적용하지 마라. 반격 진격이 없는 fixture에 T12를 성공시키거나, 돌파구가 없는 fixture에 T06을 실행해 테스트를 통과시키면 안 된다.

### 17.3 데이터 불변 조건 검사

다음은 자동으로 검사 가능한 형태로 구현해라.

- 각 지휘관의 공개된 손실 합계가 해당 원본 손실 합계와 같다.
- 같은 원본 손실의 동일 quantum이 두 번 공개되지 않는다.
- 화면 총병력이 지휘관 장부 합계와 같다.
- 음수 병력, NaN 좌표, 무한 좌표가 없다.
- 모든 combatLoss는 유효한 contactId와 원본 교전 출처를 갖는다.
- combatLoss 시각이 접촉 구간 안에 있고 양쪽 구획이 허용 접촉 거리에 있다.
- 접촉 상대는 원본 교전 관계에 연결되어 있다.
- 전사 뒤 공격이나 살아 있는 상태로의 복귀가 없다. 실제 새 인물은 별도 ID다.
- 실제 비전투 지휘관에게 combatLoss가 배정되지 않는다.
- 같은 plan과 같은 t의 평가 결과가 반복 호출 순서와 무관하게 같다.
- 연출 계획 생성과 재생 전후 원본 세계, 기록과 게임 난수 상태가 바뀌지 않는다.
- 전술 미리보기의 강제 선택 기능이 실제 게임 결과를 바꾸지 않는다.

같은 시드의 실제 시뮬레이션 비교와 재생 fixture 검사는 서로 다른 검증이다. 둘 다 수행하고 하나로 다른 하나를 대체하지 마라. 테스트가 구현의 상수를 그대로 되풀이하는 수준이면 부족하다. 잘못된 원본 연결, 접촉 전 손실, 손실 중복 등을 실제로 잡는 부정 사례도 포함해라.

## 18 완료 판정과 제출물

다음 조건을 모두 만족해야 완료다.

1. 변경 범위가 집단군 전술화면 내부와 필요한 최소 연결에 한정된다.
2. 같은 원본의 전투, 세계, 게임 난수와 전술화면 바깥 동작이 보존된다.
3. 접근, 접촉, 타격 효과, 피격과 실제 손실이 연결된다.
4. 14개 전술이 각각 식별 가능한 동작과 상대 대응으로 구현되어 실제 사용 경로에서 선택된다.
5. 여러 실제 교전이 하나의 지속되는 전장 안에서 이어지고 개별 승패를 읽을 수 있다.
6. 점령, 재탈환과 영토 유지의 차이가 원본 사건대로 표시된다. 순변화 0인 왕복 점령도 빠지지 않는다.
7. 극단적 병력 조합, 같은 지휘관의 연속 교전과 중간 패배가 처리된다.
8. 다시 보기, 배속, 일시정지와 건너뛰기의 종료 상태가 정확하다.
9. 최종 배포 파일을 실제 브라우저에서 열어 확인한다.

제출물은 다음과 같다.

- 원본을 보존한 수정 실행 HTML. 예시 파일명은 saguk_studio_tactical_screen_v2.html이다.
- 소스가 제공된 프로젝트라면 전술화면 관련 소스 변경과 빌드 결과.
- 변경 범위표: 바꾼 모듈과 함수, 이유, 다른 시스템에 영향이 없는 근거.
- 14개 전술 검증표: 구현 위치, fixture, 고유 경로와 접촉 면, 상대 대응과 실제 확인 결과.
- 극단 사례 및 연속 전개 검증표: 원본 손실과 종료 수치, 개별 승패, 점령 사건과 순변화, 재생 제어 결과.
- 적어도 한 개의 30초 이상 연속 전개 시연. 준비와 정지만 길게 찍지 말고 승패와 전선 변화가 여러 번 드러나야 한다.
- 실제 기록 또는 구분된 개발 fixture를 사용한 점령 후 재탈환 시연. 상단 영토 상태와 원래 소유권 전환을 대조할 수 있어야 한다.
- 각 전술의 짧은 시연 영상 또는 순차 스크린샷. 명령 문구만 보이는 이미지는 부족하다.
- 원본 결과 및 범위 보존 검사, 실행한 테스트 명령과 측정한 성능. 미실행은 미실행으로 적는다.

수정 실행 파일 제출을 위해 실제로 게임을 변경하는 것은 이 지시서를 받은 구현자의 작업이다. 이 문서 수정 요청 자체를 받은 작성자는 게임 HTML을 수정하지 않는다. 원본 61번은 요구사항을 확인하는 입력 파일이다.

## 19 완료로 인정하지 않는 방식

- 전술 이름과 명령 문구만 추가하거나 같은 트랙을 이름만 바꿔 재사용하기.
- 기존 타임라인을 느리게 늘려 30초를 채우거나 동일한 칼질과 대기로 시간을 채우기.
- 모든 실제 교전의 결과를 여전히 마지막 한 시점에 모아 공개하기.
- 최종 병력 차이만 다섯 번 나눠 접촉과 무관하게 공개하기.
- 마지막 승패만 보여주고 같은 지휘관의 중간 승리나 패배를 생략하기.
- 획득 0, 상실 0이라는 순변화만 보고 점령 후 재탈환을 지우기.
- 방어 승리를 영토 탈환으로, 전투 승리를 자동 점령으로, 적 진격을 무조건 적 패배로 바꾸기.
- 기록에 없는 전투, 증원, 전사, 점령이나 역전을 추가하기.
- 같은 적을 복제하거나 실제 미교전 부대에 공격과 손실을 배정하기.
- 새 전술화면의 연출을 맞추려고 게임 규칙, 지도 공개, 후퇴나 점령 시스템을 고치기.

- 현재 전술화면으로 묶이지 않는 기록까지 보이게 하려고 campaignGroups나 대상 선정 규칙을 변경하기.

## 21 지속되는 전투 전개를 만드는 방법

### 21.1 최종 결과가 아니라 원래 교전들의 전개로 구성해라

현재 집단군 묶음의 모든 engagements를 같은 시각에 resolve하는 방식을 교체해라. 각 실제 교전을 읽어 BattleBeat를 만들고, 실제 전투 결과 공개와 그 반응이 다음 전개로 이어지게 한다.

표현할 기록은 61번의 기존 집단군 묶음 안에 한정한다. 다음 턴이나 다른 집단군에 있는 재탈환을 이 화면의 결말로 끌어오지 마라. 현재 묶음에 재탈환이 없으면 이 화면에 재탈환을 만들어 넣지 않는다. 다른 묶음까지 연결하는 기능은 이번 수정 범위에 없다.

BattleBeat는 사용자에게 카드 대결을 따로 보여주기 위한 화면이 아니다. 같은 전장 안에서 어떤 구획이 어떤 상대와 언제 맞붙고, 손실을 언제 공개하며, 승패 이후 무엇을 하는지 정의하는 내부 단위다.

권장 데이터는 다음과 같다.

```ts
type BattleBeat = {
  id: string;
  sourceBattleId: number | string;
  sourceEventIndices: number[];
  territoryId: string;
  attackerCommanderId: string;
  defenderCommanderId?: string;
  winnerCommanderId?: string;
  result: 'attackWin' | 'defenseWin' | 'draw' | 'unopposed';
  previousBeatIds: string[];
  startMs: number;
  contactStartMs?: number;
  resultRevealMs: number;
  endMs: number;
  tacticInstanceIds: string[];
  contactIds: string[];
  lossRevealIds: string[];
  territoryTransitionIds: string[];
};

type TerritoryTransition = {
  id: string;
  sourceEventIndex: number;
  sourceBattleId?: number | string;
  territoryId: string;
  previousCountryId: string;
  nextCountryId: string;
  responsibleCommanderId?: string;
  kind: 'capture' | 'recapture';
  revealMs: number;
};

type TacticalStory = {
  beats: BattleBeat[];
  transitions: TerritoryTransition[];
  resultReveals: TacticalResultReveal[];
  territoryStartOwners: Record<string, string>;
};
```

이것은 개념 스키마다. 미정의 타입과 실제 필드형은 기존 코드에 맞춰 구현하고 제품 UI는 한국어를 유지해라.

### 21.2 순서와 동시 진행을 구분해 계획해라

동일 지휘관의 이전 교전 완료와 손실을 다음 교전의 시작 조건으로 연결해라. 같은 영토의 소유권 전환도 원래 사건 순서를 유지한다. 두 교전이 같은 지휘관, 접촉 공간, 영토 변경에 의존하지 않으면 접근과 교전의 일부를 겹쳐도 된다.

결과 공개는 읽을 수 있는 순서를 정한다. 독립 교전이 화면에서 동시에 진행되더라도 두세 개의 중요한 결과를 같은 순간 겹쳐 띄우지 마라. 현재 결과가 읽히는 동안 다른 구획은 다음 접근, 방어, 독립 교전과 재정렬을 지속한다.

원본 전체 사건 순서를 엄격하게 유지하는 것이 필요한 부분에서는 순서를 보존해라. 병렬 연출을 위해 동일인의 병력을 복제하거나 원래 후속 교전의 병력을 미리 공개하지 마라.

### 21.3 하나의 전장을 계속 유지해라

- 교전 하나가 끝날 때 전체 부대를 원위치로 돌리지 않는다.
- 피해를 입은 부대는 줄어든 병력과 흐트러진 대열을 유지한다.
- 승리한 부대는 해당 교전 결과에 따라 잠깐 재정렬하거나 다음 상대에게 접근한다.
- 패배한 부대는 실제 이후 활동과 생사에 맞춰 후퇴, 대기 또는 퇴장한다.
- 다음 수비대가 실제 기록에 등장하면 처음부터 식별된 후속 대열 또는 등장 구간을 사용한다. 원래 없던 지원군을 만들지 않는다.
- 방어국이 반격하면 국가는 그대로 두고 현재 전진 방향과 주도권을 바꾼다. 국가색이나 화면 양군의 소속을 서로 바꾸지 않는다.
- 다음 영토로 진격하면 현재 전장 제목과 상단 영토 표시가 해당 전개로 넘어간다. 지도 화면으로 매번 나갔다 들어오지 않는다.
- 전선의 누적 이동으로 화면 밖으로 벗어나지 않게 전술 내부 좌표와 대열 깊이를 조절한다. 지도 카메라나 사용자 줌은 바꾸지 않는다.
- 동일 전투 묶음 안에서 전술화면을 재생하는 동안 화면 전환이나 검은 화면, 카드 대결 창으로 사건을 분절하지 않는다.

전장 내부 좌표는 추상적인 전선 표현이다. 실제 지도 위치가 같은 좌표로 옮겨지는 것은 아니다. 영토 진격의 설명은 상단의 현재 영토와 실제 소유권 장부로 명확하게 구분한다.

### 21.4 모든 개별 승패를 근거와 함께 보여줘라

전술화면의 묶음에 들어온 실제 교전 결과는 모두 한 번 이상 읽을 수 있어야 한다. 중요하지 않다는 이유로 기록에서 지우거나 최종 승자만 보여주지 마라. 읽기 밀도는 짧은 부대 위 표시와 현재 교전 안내로 조절한다.

표시 예시는 다음과 같다. 다음 이름과 사건은 형식을 설명하기 위한 가상 예시이며 fixture 외 실제 기록을 만들라는 의미가 아니다.

- 진우 승리 · 청현휘 후퇴
- 백진이 청하 공격을 저지
- 청하 공방 1차 교전 · 류건 승리 · 추가 수비대와 교전 계속
- 사준 승리 · 청하 점령
- 백진 반격 성공 · 청하 재탈환
- 진우와 사준 무승부 · 영토 유지
- 방어 병력 없음 · 청하 무혈 점령

누가 승리했는지는 winner와 실제 지휘관 ID로, 누가 패배했는지는 해당 교전 상대와 실제 결과로 결정한다. 원래 공격 측의 success만으로 전체 국가 승패를 판단하지 마라. 소속 국가와 그 교전의 공격 및 방어 역할이 반격 중 바뀔 수 있다.

승리한 부대 근처에 짧은 승리 표시를, 패배한 부대에는 후퇴 등 실제 반응을 붙여라. 상단에는 현재 교전의 주체와 영토를 표시해라. 전사하지 않았는데 패배했다는 이유로 지휘관을 사라지게 하지 않는다.

공세의 최종 요약은 각 사건을 대신하는 장면이 아니라 이미 본 흐름의 정리다. 중요한 개인 성과와 영토 변화는 본편에서 먼저 드러나야 한다.

## 22 점령과 재탈환을 위한 읽기 전용 영토 장부

### 22.1 순변화만 사용하지 마라

현재 plan.changes의 전후 차이는 최종 순변화다. A국 영토가 B국으로 넘어간 뒤 A국으로 돌아오면 이 값은 0일 수 있다. 사용자는 이 과정 자체를 보고 싶어 한다.

전술 전용 TerritoryTransition은 원래 events와 frames의 실제 소유권 변경, 교전별 takenTerritoryIds, record.changes와 captureOwner 등의 기존 정보를 교차 확인해 구성해라. record.changes는 순차 자료로 활용하되 책임 지휘관과 실제 변경 시점이 부족하면 해당 battle과 event frame을 함께 읽어라.

어떤 한 필드만 추정해서 점령을 만들지 마라. continuation이 counter라는 이유만으로 재탈환으로 표시하지 말고 실제 소유권 전환을 확인해라. 방어 승리, 반격 시도, 영토 획득은 서로 다르다.

원본 이벤트 프레임에서 소유권이 resolve와 함께 이미 바뀌는 경우 그 사건을 진실의 기준으로 삼고, 연출에서는 해당 교전 결과 공개 직후 또는 함께 표시한다. 점령을 보여주기 위해 engine의 소유권 변경 시점을 바꾸지 마라.

### 22.2 표시 장부의 갱신

전술 시작 시점의 소유권 사본에서 출발하고 현재 재생 시각까지 공개된 TerritoryTransition만 적용해라. 뒤에 일어날 재탈환이나 점령을 전투 초반에 색이나 제목으로 먼저 보여주지 마라.

예를 들어 원본 기록이 다음과 같다면 두 사건을 모두 보존한다.

1. 청하 소유 A국.
2. B국 사준이 승리하고 청하를 점령.
3. A국 백진이 이후 승리하고 청하를 되찾음.

이때 표시 흐름은 A국 소유, B국 점령, A국 재탈환 순서다. 최종 순변화는 0으로 유지한다. 점령 사건 2회와 최종 변화 0개는 다른 지표다.

재탈환은 현재 묶음이나 이미 제공된 과거 기록에서 해당 국가가 그 영토를 소유했다가 빼앗겼다는 근거가 있을 때 사용한다. 근거가 없으면 점령으로 표시해라. 재탈환 판정을 위해 새 전역 영토 역사 저장 시스템을 추가하지 마라.

지휘관의 점령 책임은 그 실제 교전과 소유권 변경에 연결되는 인물만 표시한다. 책임자를 특정할 수 없으면 국가와 영토만 표시하고 현재 대표 지휘관 이름을 임의로 붙이지 마라.

동일 소유권 사건이 resolve, capture, occupation 이동 등 여러 표현으로 나타나도 점령 사건은 한 번만 세어라. 실제 소유권 전환 ID와 출처 사건을 기준으로 중복을 제거하고, 지휘관이 점령지로 이동한 사건을 두 번째 점령으로 세지 마라.

### 22.3 전술화면에서의 표시

기본 제안은 상단 기존 전장 제목 영역에 작은 영토 표시줄을 넣는 것이다. 현재 교전 영토를 강조하고 이미 공개된 영토의 현재 소유 국가색을 보여준다. 영토가 많으면 현재 영토와 가까운 최근 사건 위주로 표시하고 긴 목록을 펼쳐 전장을 가리지 마라.

점령 순간에는 영토명, 획득 국가, 책임 지휘관을 읽을 수 있게 표시하고 부대 전진 또는 상대 후퇴와 연결해라. 재탈환 순간에는 같은 영토의 색이 다시 바뀌고 재탈환 문구가 나와야 한다. 전선 유지라면 소유권 색을 바꾸지 않는다.

전장 안에 실제 지형과 다른 가짜 성을 필수로 세우거나 실제 지도 전체를 다시 구현할 필요는 없다. 기존 병력 전장과 작은 영토 상태 표시만으로 흐름을 설명해라.

종료 요약에는 실제 개별 승패 요약과 함께 최종 영토 순변화, 필요한 경우 점령 및 재탈환 과정이 구분되어야 한다. 기존 plan.gained와 plan.lost의 의미를 공용 로직에서 바꾸지 말고 화면 전용 별도 집계로 추가한다.

### 22.4 엄격한 지도 경계

이 영토 장부는 전술화면의 설명을 위한 사본이다. 기존 massBattleRecap의 지도 공개 장부와 합치거나 교체하지 마라. 전술 종료 뒤 지도에서 언제 어떤 색과 위치가 공개되는지는 61번의 기존 동작을 그대로 유지한다.

전술화면에서 이미 점령 문구를 읽었다고 지도 점령 장면을 생략하거나, 지도 소유권을 앞당기거나, 이동 애니메이션을 짧게 만드는 것은 금지다.

## 23 지속 전개 시연의 구체 예시

아래 60초 안팎 시간표는 원본에 해당 사건이 모두 있는 가상 검증 기록을 가정한다. 모든 전투에 이 줄거리를 강제하지 마라. 실제 자동 선택 전투에서는 해당 묶음의 사건으로 구성한다.

| 대략 시각 | 전장 동작 | 공개할 실제 정보 |
| --- | --- | --- |
| 0~5초 | 대치와 접근, 중앙과 양익 전개 | 최초 소속과 총병력, 현재 교전 영토 |
| 5~14초 | 중앙 교전과 측면 견제, 접촉 시 손실 | 진우가 청현휘에게 승리, 추가 수비가 남아 점령은 아직 없음 |
| 14~24초 | 승리 부대가 재정렬하고 실제 다음 수비대와 교전, 다른 날개는 계속 싸움 | 진우가 후속 교전에서 패배, 앞선 승리 표시는 기록에 유지 |
| 24~34초 | 사준의 부대가 같은 영토의 다음 공격을 이어감, 방어 전열이 밀림 | 사준 승리, 실제로 청하 소유권이 B국으로 변경 |
| 34~46초 | 원래 방어국의 백진이 반격, 공격국 부대가 방어로 전환 | 백진 승리와 청하 재탈환, 실제 손실과 생존 부대 유지 |
| 46~56초 | 다른 구간의 실제 교전이 정리되고 패배 부대가 철수 | 각 장수의 남은 실제 승패, 전사 사건이 있다면 해당 사건만 표시 |
| 56~60초 | 잔존 병력과 전선 정리 | 청하 소유권 복귀와 최종 순변화 0, 개인 성과 요약 |

시연에서 확인할 핵심은 진우가 승리했다가 패배하는 것을 둘 다 알 수 있고, 사준의 점령과 백진의 재탈환이 별개 사건으로 읽힌다는 점이다. 종료 화면의 국가 승패 한 줄로 이를 대체하지 마라.

같은 지휘관이나 영토의 기록을 다른 시각에 보여줄 때 최종 상태를 미리 넣지 않는다. 14초 시점에 나중 패배한 진우를 이미 후퇴 상태로 만들거나, 사준이 점령하기 전부터 청하를 백진 재탈환 상태로 표시하면 실패다.

원래 묶음에 추가 수비대와 반격 기록이 없다면 이 예시처럼 보이게 만들지 마라. 실제 결과가 단순하면 접근, 전열 교환, 손실, 저지와 철수의 세부 움직임을 풍부하게 하되 교전 결과를 새로 늘리지 않는다.

## 24 다른 시스템을 건드리지 않았다는 검증

기준 단일 HTML을 풀어 논리적 모듈과 자산 단위로 비교해라. 압축된 배포 문자열 전체가 달라졌다는 이유만으로 범위 검증을 생략하면 안 된다.

원칙적으로 다음은 내용 해시가 동일해야 한다.

- engine, model 및 실제 기록 생성 어댑터.
- 지도 렌더러, 지도 소유권 및 병력 표시, 카메라와 줌.
- 집단군 구성과 묶음 선정, battleEntry, massBattleRecap 및 지도 공개 처리.
- 일반 전투와 촬영 모드, 저장과 불러오기, 설정과 세계 편집.
- 기존 이미지 및 오디오 원본 데이터. 이번 작업으로 새 자산 제작은 요구하지 않는다.

공용 파일 안에 전술화면 함수가 함께 있어 파일 전체 해시가 달라질 수는 있다. 이 경우 함수 단위 diff와 분기별 실행 검증으로 해당 화면 밖 경로가 같음을 확인해라. 전술화면이 꺼진 경우 해당 변경 코드가 실행되지 않는지 검사한다.

전술화면 앞의 지도 장면 순서와 뒤의 recap 및 복귀 장면 순서는 61번 기준과 같아야 한다. 각 비전술 장면의 worldBefore, worldAfter, camps, mapEventIndex, mapReveal, mapAfterReveal, 이동과 점령 대상은 기준과 동일해야 한다. 전술 본편의 길이가 늘면서 실제 벽시계 기준으로 뒤 장면이 늦게 시작되는 것만 허용한다.

원본 입력 세계와 기록을 freeze한 개발 검증에서 전술 계획 생성 및 임의 시점 평가를 수행해 쓰기 시도가 없는지 검사해라. 같은 시드의 엔진 결과, 기록 스키마와 다음 턴 난수 상태도 비교한다.

추가 자동 검증은 다음과 같다.

- 모든 원본 교전 결과가 정확히 한 번의 결과 공개 사건에 연결된다.
- 모든 실제 소유권 전환이 정확히 한 번의 TerritoryTransition에 연결된다.
- 동일 영토의 사건 순서가 원본과 같고 순변화 0인 왕복 전환도 남는다.
- 아직 공개되지 않은 결과, 생사와 영토 소유권이 초반 화면에 노출되지 않는다.
- 같은 지휘관의 다음 교전 시작 병력이 직전 교전과 실제 증가 및 감소 사건에 맞는다.
- 14개 전술의 강제 시연 경로와 실제 자동 선택 경로가 같은 구현을 사용한다.
- 단일 교전 카드로 화면이 리셋되지 않고 부대의 위치와 줄어든 병력이 이어진다.

전술화면 외 변경이 검증에서 발견되면 그 변경을 되돌려라. 다른 시스템을 손본 뒤 결과만 같으니 괜찮다고 판단하지 마라. 경계를 지키는 구현이 불가능한 세부사항은 미구현 범위와 이유를 정확히 보고하고 실제 변경을 강행하지 않는다.

## 25 사용자 확정 기준과 고정 요구사항

사용자는 아래 추천안을 채택했다. 일반 및 복잡한 전투의 길이는 확정 기준으로 적용하고, 사건이 매우 많은 경우의 연장은 예외로 처리해라. 동일 항목에 대한 재확인 없이 구현을 진행한다.

| 항목 | 적용 기준 | 적용 범위 |
| --- | --- | --- |
| 일반 집단군 길이 | 기본 속도에서 30~45초 | 전술화면 내부 시간표만 |
| 복잡한 진격과 반격 | 기본 속도에서 60~90초 | 실제 사건의 읽기 시간 우선 |
| 사건이 매우 많은 경우 | 90~120초까지 허용 가능 | 가짜 교전과 반복 대기로 연장 금지 |
| 일반 교전 결과 읽기 | 약 2~3초 | 짧은 부대 표시와 상단 현재 교전 |
| 점령 및 재탈환 읽기 | 약 3~4초 | 실제 원본 소유권 전환만 |
| 영토 표시 방식 | 기존 제목 영역의 작은 영토 상태줄 | 우측 설명란과 하단 규칙란 없음 |

일반 30~45초, 복잡한 경우 60~90초는 사용자가 승인한 길이다. 기존 16~18초보다 길어지지만 전투 흐름을 읽을 수 있게 한다는 목적에 맞춰 적용해라. 1배속 기준이며 기존 4배속과 8배속 및 다른 모드의 재생 정책은 그대로 유지한다.

다음은 이미 사용자 지시로 확정되어 재확인이 필요 없는 요구사항이다.

- 집단군 전술화면만 바꾼다.
- 다른 시스템, 게임 결과와 지도 연출은 건드리지 않는다.
- 전투가 한 번 부딪히고 끝나는 형태를 벗어나 지속되는 흐름을 보여준다.
- 누가 이기고 졌는지, 어떤 영토를 빼앗고 되찾았는지 읽을 수 있어야 한다.
- 앞서 정의한 손실 동기화, 14개 전술 구분과 극단 병력 조합을 반영한다.

전술화면 구현자는 최종 보고에서 적용한 기준 시간값과 실제 재생 길이를 함께 적어 사용자가 플레이 후 조정할 수 있게 해라. 이 때문에 새 전역 설정 화면을 만들거나 기존 배속을 수정하지 않는다.
