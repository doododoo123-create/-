# v0.59.0 전술·양측 명령·변경 이유

사용자가 승인한 관전 보완12항목과 전술/명령 안내를 적용했다. 실제 주사위·게임 RNG·손실·승패·영토·거리·피로·인물 능력·저장 형식은 변경하지 않는다. 원래 기록으로 정해진 전투를 설득력 있게 보여주는 전술창의 수정이다.

## 화면에서 읽는 방법

상단에 **현재 전술**과 **발동 이유**를 계속 표시한다. 그 아래 왼쪽은 **공격군 명령**, 오른쪽은 **수비군 명령**이다. 반격에서는 원래 수비군이 주도권을 잡고 공격군이 대응하는 명령을 받는다. 전술이나 주도권이 바뀌면 `전술 변경 · 이전 → 현재`를 표시한다. 동일한 명령을4.2초마다 반복하던 방식은 제거했다.

예를 들어 편익 공세에서는 공격군이 `화면 위쪽 날개에 공세를 집중하라`는 명령을, 수비군이 `화면 위쪽 날개에 후열 병력을 보내라`는 명령을 받는다. 해당 방향의 접촉면을 압박하고, 실제 수비 후열의 빈 병사 구획을 그 구역 뒤로 이동시킨다. 실제 원본 장수의 구획만 이동하며 가짜 지휘관/적/병력을 추가하지 않는다.

명령 변경의 계기는 전열 접근, 실제 접촉, 이미 공개한 승패·돌파·역공, 예비대 도착, 전체 판정 종료다. 성립하지 않은 돌파/반격 결과를 이유로 먼저 발표하지 않는다. 별도의 연출 시드를 유지하므로 같은 기록과 버전은 같은 동작으로 재생된다.

## 12항목 적용

| 항목 | 구현 내용 |
| --- | --- |
| 1. 동작 완주 | 걷기/후퇴 시계를 연속 경로 전체에서 유지한다. 공격770ms와 방어830ms를 각각 끝까지 재생한다. 상대 변경이 동작 시계를 초기화하지 않는다. |
| 2. 때리고 맞는 반응 | 원본 손실을 실제 공격자 동작의340ms 타격에 연결하고330ms 피격 동작과 충돌/먼지/손실 표식을 사용한다. 기존 금속·방패 소리를 실제 접촉 타격에 연결한다. 시각적 충돌 자체가 새 피해를 발생시키지는 않는다. |
| 3. 병사 가독성 | 전장을1920×760으로 가로 창에 맞추고 안전 간격을 줄여 몸체를 과도하게 축소하던 문제를 완화한다. 기본8/만·한쪽480/양국960 상한과 공통 축소율은 보존한다. 병사 수를 장수별 최소치로 늘리지 않는다. |
| 4. 소속 구분 | 같은 장수의 모든 구획에 같은 국가색 번호 깃발을 붙인다. 이름표는 평균 빈 공간이 아닌 실제 병사 구획에 붙으며 연결선을 사용한다. 이름/병력/잔존 막대/상태와 역할·성향을 표시한다. |
| 5. 부대 역할 | 기동형은 측면, 신중형은 후열, 수비형/왕은 방어선, 돌격형은 선두로 배정한다. 일부 작은 부대와 실제 대기 인원은 예비대를 맡는다. 개인 능력과 병력은 대표 선정에 읽기만 한다. 역할 표식●/◆/▰/▾을 구별한다. |
| 6. 전술별 모양 | 중앙은 실제 접촉면의 중앙, 편익은 화면 위/아래 날개를 기준으로 선정한다. 협공/우회는 외곽 기동, 돌파는 진행 방향의 쐐기/종대, 수비는 굽힌 방어 대열, 파상/후속대는 실제 구획 교대를 사용한다. |
| 7. 상대 대응 | 양측에 서로 다른 명령을 부여한다. 측면/중앙 압박에 후열을 이동시키고, 파상 공세 때 양측이 자기 장수의 구획을 교대한다. 예비대가 없거나 진입 공간이 막힌 경우 통로를 비우며 전열이 버틴다. |
| 8. 전술 변경 계기 | 이미 공개한 교전 결과, 돌파/반격, 실제 예비대 도착에 반응한다. 변경 이유와 이전/현재 전술을 표시한다. 대표가 전사하면 생존 지휘관으로 명령을 이어받는다. |
| 9. 전선 확보 | 접촉면의 압박 방향을 주도 측에 연결하고 교전선을 표시한다. 승리 직후 위치를 유지할 시간을 확보한다. 종료 시 마지막 교전에 승리한 부대는 위치를 지키고, 패전 부대들은 함께 후방으로 물러난다. 점령 표식은 실제 소유권 공개 시점에 나온다. |
| 10. 자연스러운 이동 | 연속 이동 시계를 유지하고, 전체 몸체의 이동 공간이 비어 있는 모서리에만 곡선을 적용한다. 혼잡한 진입로에서는 예약된 안전 경로를 사용한다. 상대 구획·대기·퇴각까지 같은 점유 표에 포함한다. |
| 11. 목표와 지형 | 현재 목표 지역과 진영 후방을 표시한다. 원본 기록의 산악 전투에는 산악 방어선 표식과 방어 역할을 적용한다. 실제 점령/재탈환 때 해당 접촉면에 국가색 깃발과 구분 문구를 보여준 뒤 기존 지도 결과 재생으로 이어진다. |
| 12. 규모별 템포 | 소수전에는 복잡한 협공/파상/예비대 정책을 제한한다. 대규모 전투는 공통 전장 안에서 다른 교전이 이어지며 결과를 공개한다. 불필요하게 같은 기동을 반복해 접촉을 끊지 않는다. 기존 배속/정지·중요 사건1배속·요약1초는 유지한다. |

이동할 공간이 부족하면 모든 부대를 같은 지점에 넣지 않고 후열 대기/교대를 사용한다. 접촉 중인 전열의 이동 뒤에도 진입·퇴로를 다시 검증한다. 기존 부대가 다음 부대의 도착점을 막은 경우, 다른 전열이 통로를 비운 뒤 진입한다. 순간이동으로 막힘을 숨기지 않는다.

## 구조와 유지 범위

- `tactical-director.js`: 사건별 전술·변경 이유·양측 명령·생존 대표.
- `tactical-roles.js`: 원본 성향/병력을 읽는 화면용 역할·번호.
- `tactical-motion.js`: 완전한 병사 동작 시계, 타격 시각, 안전한 곡선 경로.
- `tactical-armies.js` / `tactical-field.js`: 공간 예약, 중앙/날개 기동, 교대·증원·퇴로.
- `tactical-sample.js`: 임의 시점의 피격/이름표 부착점/전술 상태.
- `tactical-drawing.js`: 교전선, 목표/산악, 번호/역할, 타격/점령 표식.
- `mass-battle-view/css/animation`: 지속되는 전술·명령·이유와 단일 캔버스 렌더링.

원본 `tactical-record` 장부를 유지하며 최종 차이를 가짜 피해로 나누지 않는다. 보호된 게임 엔진/모델/저장/지도 카메라/공용 재생기와 소리 믹서·디렉터는 그대로다. 기존4음 제한·음량·배속에 따른 음높이 보존·일시정지/건너뛰기를 사용한다. 전술창 밖 지도/진입3모듈은 사용자 파일61(v56) 바이트 기준을 유지한다. 선택 턴 녹화의 전술화면 켜기/끄기와 일반 일대일 화면도 유지한다. 새 이미지/폰트/CDN/외부 서비스는 추가하지 않았다.

## 검증

`npm test` **684개 모두 통과**, `npm run check` **372개 JavaScript 구문 검사 통과**. 원본 교전별 정수 손실, 공격 타격/피격 일치, 실제 전사, 역공·추가 진격·왕 방어,14전술, 임의 시점 탐색/재생, 모서리 이동 포함 전체 몸체 비겹침, 같은 기록 재현을 검사했다. 엔진/저장 보호 해시, 기존42지도 장면,8개 시드의96국가 차례도 일치했다.

실제 Chromium에서 다음3조건을2배속으로 연속 재생했다. 병사 수/동시 교전/부대 겹침/접촉 중 이동/최종 병력과 각 단계의 전술·명령·변경 이유를 확인했다.

| 조건 | 시작 그림 합계 | 최대 동시 접촉면 | 몸체 겹침 |
| --- | ---: | ---: | ---: |
| 1만:1만 | 16 | 1 | 0 |
| 5장수5만:3장수30만 | 280 | 4 | 0 |
| 15장수60만:1장수1만 | 488 | 2 | 0 |

세 조건은 표시 검증용이며60만 단일 지휘관을 실제 규칙으로 허용한 것이 아니다. [실측 장부](v59-browser-results.json)와 [교전 화면](v59-tactics/five-contact.jpg)을 남겼다.

실제 일반/추가 진격/역공/전사 기록은800×500 창으로 열어 모든 명령 단계를 검사했다. 각 단계의 문구가 계획과 같고 양측 명령이 서로 다르며, 변경 알림·목표 소유권 공개가 일치했다. [명령 검사 장부](v59-orders-browser.json), [작은 창](v59-tactics/normal-orders.jpg), [역공](v59-tactics/counter-orders.jpg)을 참고할 수 있다. 실제 단일 HTML에서도 불러오기 후 네트워크를 끄고 선택 저장·전술 끄기·지도 후퇴/점령·다시 켠8장수 전술창/명령·병사 깊이 순서·지도 복귀를 확인했다.

```sh
npm test
npm run check
npm run release
node tests/make-v59-demos.mjs
python tests/tactical_v59_visual.py
python tests/tactical_v59_orders.py
python tests/selected_battle_v59_smoke.py
```

브라우저 검수에는 개발용 Python Playwright와 로컬 Chromium을 사용했다. 실행 HTML에는 이 도구가 필요 없다. 프레임 캐시/단일 캔버스/기존 RAF를 재사용하며 모든 기기의 성능이나 모든 배치의 연출 품질까지 보증하는 검사는 아니다. 일반 단일 HTML만 제공한다.
