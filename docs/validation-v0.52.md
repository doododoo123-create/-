# v0.52.0 기록 기반 집단전 첫 구현

현재 저장소/GitHub의v0.51.2를 바탕으로 사용자가 승인한 부대 꾸러미 전투와14개 전술 정책 조합을 구현했다. 첨부 PNG8장과 설명은 docs/reference/mass-battle-v52에 원본으로 보존하며 실제 인물/병력/시간표를 그 예시로 고정하지 않는다. 별도 AI/API나 신규 전투 규칙을 사용하지 않는다.

## 구현 범위

집단군 공세의 실제 원래 장면 범위를 분석하고 부대별 경로/교전 창/손실/후퇴·전사·재편/진격을 시간표로 만든다. 공유 인물/같은 수비 영토/연속 진격·역공/점령·중요 사건의 의존 순서는 유지하고 독립적인 이동·대기·압박을 겹쳐 보여준다. 한 부대가 같은 시각 두 경로로 움직이지 않는다. 실제 교전하지 않은 대기 부대에는 가짜 손실/격퇴를 부여하지 않는다.

새 전투 화면은 큰 초상/다이스 대결표 대신 개인별8~16병사·이름·현재 병력·잔존 막대·양측 참전 합계·필요한 짧은 알림을 표시한다. 병력 그림 수는 실제 군대를 만드는 값이 아니다. 부대별 수를 따로 보존하며 지도v0.51.2의개인별1~3병사 표시는 그대로다. 전사와 병력0 생존을 구별하며 왕은 방어 전용이고 전투 뒤 원래 기록의 위치로 돌아간다.

한 그룹이 끝나면 그 그룹의 실제 마지막 세계/주둔/영토 상태로 지도에 복귀한다. 미래의 다른 전선·충원·계절 정산을 먼저 보여주지 않고 같은 개별 대결/손실/후퇴를 두 번 자동 재생하지 않는다. 기존 원래 장면과 실제 주사위/모든 보정은 요약의상세 기록에 보존한다. 단독1대1·무방비 진입은 기존 간단한 화면이다.

일반 집단전은1배속12~18초다. 선택 배속에 연동하며 전사·수도 함락·멸망/임관 중요 알림은1배속 구간을 확보해 전체 시간은 그만큼 늘 수 있다. 종료 요약은 배속 무관1초다. 정지/배속/다시 보기/상세 복귀/건너뛰기/지도 복귀와 기존 역사·선택 턴 촬영을 연결했다. 지도 배율/시점은 전투 화면 때문에 변경하지 않으며 전투 중 방향키는 해당 영역의 스크롤을 조작한다.

## 전술 정책과 실제 선택 조건

최대4개를 별도 연출 시드로 조합하며 아래 모든 전개를 매 전투에 강요하지 않는다. 각 정책은 이동 폭·측면 곡선·대기 위치·전진/후퇴 경로에 적용한다. 전술명으로 실제 보정/새 승패를 만들지 않는다. 조건이 없으면 단순한 정면 교전/실제 후퇴를 사용한다.

| 정책 | 필요한 기록 |
|---|---|
| 중앙 집중 돌파 | 교전 승리 뒤 실제 점령 진격 |
| 편익 집중 공세 | 복수 공격 부대 중 실제 승리 부대 존재 |
| 사선 진격 | 서로 다른 부대의 점령 진격이 이어짐 |
| 양익 협공 | 복수 승리 공격 부대·복수 수비 부대,공격국 영토 순손실 아님 |
| 편익 포위 | 승리 공격 부대·양측 복수 부대,공격국 영토 순손실 아님 |
| 돌출부 확대 | 실제 추가 진격 점령 |
| 파상 공세 | 서로 다른 공격 부대가 같은 수비대와 순차 교전 |
| 집중 압박 | 같은 실제 수비대에 대한 복수 부대의 교전 |
| 후속대 투입 | 실제 구원 기록 또는 늦게 참전한 지휘관 |
| 전선 유지 | 실제 방어 승리 |
| 단계적 후퇴 | 실제 후퇴 이동과 이어지는 다른 교전 |
| 국지 역습 | 실제 방어 승리의 상대 밀어내기 |
| 반격 돌파 | 실제 역공과 점령 |
| 분리된 철수 | 복수 부대의 마지막 교전 패배 |

- 새 전투 검사16개 통과. 실제4대4,1대다수/다수대1,단독1대1,무방비,실제 무승부,연속전,역공/추가 진격,왕 수비,전사/재편,다른 전선 분리,모든14정책의 자격/선택,시드 재현,중복 손실 방지,정밀도/최종 병력,단일 경로·연속 위치,재생/정지/배속/상세/지도 복귀와 소리 장부 키를 검사한다.
- 8개 초기 시드의96개 국가 차례/집단전32개를 UI 처리한 경로와 원래 처리 경로에서 비교했다. 게임 RNG 상태·교전 지문·전체 엔진 상태·세계·다음 차례·저장 복원/역사 재생이 일치한다. src/engine·src/model·src/storage의 소스 변경은 없다.
- 실제32명/42교전 세계를 엔진에서 생성하고 초기 표시 병사512개/32개 인물ID를 보존한다. 원래 종료 상태와 마지막 보정 직전 병력도 비교해 마지막 순간 숫자로 덮어 맞추는 점프가 없음을 확인한다.
- 기존 JavaScript328개와 재현용 자료 생성 스크립트1개 구문 검사 통과. 마지막 방향/화면 가림·재생/편집 화면 분리 보정 뒤 관련38개를 재검사해 모두 통과했다. 단일 일반HTML 생성,루트/dist 바이트 일치,git diff --check 통과.
- 오프라인 Chromium1600×1000/DPR2의 실제 내보낸 역사로 전용 화면을 확인했다. 8명/현재 병력·캔버스 DPR·정지 픽셀 유지·움직임·레이블 위치·일시정지 중 배속 변경/캔버스 노드 재사용·요약 고정1배속·상세 원래 판정·같은 상태로 복귀·다시 보기·건너뛰기·지도 복귀가 통과했다. 전사 알림을 실제16배속에서 진입해1배속 보호와 정지를 확인했고 일반 화면에서도 동작한다. 앱 예외/외부 요청 실패0이다. 시간은 가짜 시계를 사용한 기능 검사다.
- 최종 실행본의32명/512병사를 오프라인 Chromium/DPR2에서 다시 확인했다.32개 불변ID와512개 그림 수,정지 상태 유지,실제 빨강/파랑 병사 픽셀,앱 예외0을 통과했다. 지도 가림층의opacity0/inert를 확인해 기존 카드가 전투 위로 비치거나 클릭되지 않게 했다. FPS 측정은 아니다.

화면 검사를 재현하려면 먼저 `node tests/make-v52-fixtures.mjs`와 `npm run build`를 실행하고,Playwright/Chromium을 준비한 뒤 `python tests/mass_battle_v52_smoke.py` 및 `python tests/mass_battle_v52_large_smoke.py`를 실행한다.

## 성능과 남은 범위

병사 시트/국가색 프레임 캐시를 기존 지도와 공유하고,하나의 캔버스·기존 RAF/재생 시계를 사용한다. 배경은 크기 변경 시만 만들고 동일 전투의 DOM/캔버스를 재사용한다. 끝난 장면의 참조/밀도 이벤트를 정리하고 비활성 지도 병사 애니메이션을 쉬게 한다. 실제 성능 FPS나 모든 기기에서 무지연을 측정·보장한 것은 아니다.

첫 구현은 기존3/4방향 그림과 좌우 반전이다. 자유 방향 전용 그림/3D·병사별 물리/신규 전투AI·매복/기만전술 성공 판정은 추가하지 않는다. 연출 시드는 계획 버전1과 기록에서 자동 결정하고 새 앱 설정이나 재추첨 버튼은 추가하지 않았다. 같은 파일·기록·연출 시드는 같은 움직임을 만든다. 많은 참가자는 크기/스크롤로 모두 접근할 수 있으며 움직이는 부대가 아주 조밀해지면 일부 그림은 겹칠 수 있다.
