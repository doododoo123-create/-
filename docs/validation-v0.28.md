# v0.28.0 검증 · 2026-10-26

## 적용한 범위

정비 표시 글씨/박스 통일,혼란 순간 안내와 얼굴 아래↓/↓↓,정비 진입 시 혼란0,시점 고정S·건너뛰기Shift+S,고정을 꺼도 국가 차례마다 한 번 이동을 구현했다. 글꼴·저장 한도·화살표 개선은[검토 문서](fonts-storage-and-arrows-v0.28.md)에 보고했다. 세계 불러오기 한도·새 진행 파일 가져오기·화살표 경로는 임의 변경하지 않았다.

엔진28이며 세계schema2/실행version1이다. 새 resetConfusionOnRest의 누락은false,새 기본160과 새 밸런스 전체 적용은true다. 화면 변경은 구형 실행에도 적용하지만 계산 변경은 새 실행부터다.

## 자동 검사

`npm test`: **384개 통과,실패0**. 기존374개와 이번10개를 포함한다. `npm run check`: 전체 JavaScript 구문 검사 통과. 두 최종 HTML의 실제 내장 스크립트도 별도 구문 검사하고 루트/dist 바이트 일치를 확인한다.

추가 검사:

- 점수차·잔여 병력·절반·혼란 한도 중 어느 이유로 정비하든 혼란은0,전쟁 끝 정비만 해제된 뒤도0 유지.
- 기존 설정이 꺼져 있으면 옛 계절 혼란 정책 보존.
- 얼굴의↓/↓↓가 혼란2/4와 대응하고 정비·전사 시 사라짐.
- 실제20만 수비대가 서로 다른 공격 장군3명을 상대해 경미하게 연속 패배: 혼란2→4→정비/0. 카드 표시는 머리글 대신 화살표,정비 글씨는 기존 상태 클래스와 같은 렌더러 사용.
- 혼란 안내는 공개된 손실 적용 단계에서만 한 번 표시하고 그 뒤 정적인 머리글이 남지 않음.
- 새 초기화 사건이 저장/재생에서 동일하고 현재 경기 불변.
- 시점 고정 꺼짐은 국가 차례당 한 번 이동,이후 같은 국가의 사건에서 수동 이동·줌 유지. 켜기/끄기는 게임/기록/난수를 변경하지 않음.
- 실제v27 커밋c52ff6b에서 만든 전쟁 저장(`fixtures/v27-active-readiness.json`)의 잔여 혼란2를 새 엔진이 보존. 모든 전투 재생과 다음 차례 상태/RNG가 당시 엔진과 일치.
- 신규160 기본 생성기만 초기화 규칙을 켜고 기존v27 생성기는 이전 정책 유지.

기존v26 실제 전쟁/수도 함락·이동 기록 대조와 원본v11 전체100라운드 대조도 전체 검사에서 유지했다. 이번 혼란 초기화 이후의32시드 장기 승자 비교를 새로 수행한 것은 아니며,이전v27의 통일 속도/승자 표본을v28 결과로 재인용하지 않는다.

## 실제 오프라인 브라우저

일반판/모바일 경량판을 외부 연결 차단 상태로Chromium에서 각각 실행했다. 단일 HTML 안의 코드·그림·소리만 사용했다.

- 실제 저장된 전투를 역사 클릭으로 재생해 혼란 순간 안내,1/2화살표,정비 중/화살표 없음 확인.
- 정비 글씨의 계산된font-size8px,텍스트의 실제 글자 경계가 배경 박스 안에 들어가는지 측정.
- S로 추적 켜기/끄기,Shift+S로 기존 결과 건너뛰기,입력/select를 조작할 때S가 끼어들지 않는지 확인.
- 꺼진 상태에서 방향키로 이동한 구도가 현재 국가 전투 중 유지되고,다음 국가 차례에는 한 번 이동함을 확인.
-390×844와844×390에서 시점 버튼·소리·재생·달력이 화면 안에 있고 서로 겹치지 않음.
- 역사 재생·시점 전환 전후 현재 경기 저장이 같고 새로고침하면3차례 기록이 복원됨.
- 완전히 새 저장 환경의 기본160 지도와 초기화 체크 기본 켜짐 확인.
- UI 예외/실패한 외부 요청0. 실물 휴대전화의 성능/발열 측정을 했다는 의미는 아님.

```sh
npm test
npm run check
npm run release
python3 tests/studio_v28_smoke.py
```

브라우저 검사는3000포트의`npm start`,Python Playwright와Chromium이 필요하며 검사 스크립트가 실제 기록 시나리오를 자동 생성한다. 일반 사용자는 HTML만 열면 된다.
