# v0.58.0 집단군 전술화면: 1~5번 적용

전투 판정·난수·손실·승패·영토 결과를 바꾸지 않고, 전술창의 연출 계획을 수정했다. v0.57.1에서 만든 선택 턴 녹화용 **집단군 전술화면** 체크칸은 유지한다.

## 바뀐 동작

1. **군 전체의 공통 전장.** 모든 참가 부대에 전열·측면·예비대 역할과 공통 시간을 부여한다. 서로 다른 실제 상대의 접촉면에서 동시에 교전한다. 같은 장수가 연속 상대를 만날 때마다 접근→전투→후퇴 장면을 처음부터 만들지 않는다. 원본 교전 기록은 실제 상대, 손실, 승패와 점령 공개의 근거로 사용한다. 결과를 읽는 동안 다른 전선은 움직이고 싸운다.
2. **절대 병력 축척.** 기본은 1만 명당 병사 그림 8개다. 한쪽480개·양국 합계960개 상한을 넘을 때만 양국에 같은 축소율을 적용한다. 5만:30만은40:240, 1만:60만은8:480이다. 지휘관마다 최소 병사 수를 추가하지 않는다. 정수가 아닌 배분은 국가 전체 합계를 먼저 맞춘 뒤 나머지가 큰 부대부터 배분한다.
3. **전장 전체의 공간 예약.** 부대의 점 하나가 아니라 병사 그림 전체의 가로·세로를 예약한다. 대기·진격·교전·복귀 부대를 모두 같은 점유 표에서 다룬다. 진입로와 복귀로에 방향을 두고, 앞 부대가 비운 공간으로 뒤 부대가 이동한다. 모서리에서 몸체가 겹치는 교차와 맞교환을 막는다. 공간이 부족하면 후열에서 기다리거나 교대한다. 순간이동으로 길을 비우지 않는다.
4. **접촉 이후의 움직임.** 접촉면을 함께 밀고 물러나며 측면 진입과 후속대 교대를 진행한다. 전술별로 이동 방향·대상 전열·진행 간격·대열 형태를 달리한다. 원본의 실제 손실은 해당 상대의 타격 프레임에 정확히 한 번 공개한다. 끝은 마지막 이동과 결과를 읽는 시간으로 정하며, 길이를 맞추기 위한 정지 화면을 덧붙이지 않는다.
5. **고정 크기와 명확한 결과.** 전장 좌표는1260×760으로 고정한다. 지휘관 수 때문에 높이를 늘리지 않는다. 결과 제목은 해당 지역 이름과 승자/패자를 함께 쓰고 점령·재탈환을 구별한다. 다음 전장 이름에 이전 결과 문구를 붙이지 않는다. 전술창 밖 `atlas-view`, `army-presentation`, `battle-entry`는 사용자 파일61인 v0.56.0과 바이트가 같다. 기존 지도 후퇴·점령 결과 재생은 그대로 사용한다.

부대의 그림 수와 그림 한 개의 크기는 별개다. 고정 전장에 진입로·퇴로까지 확보하기 위해 몸체 크기를 양국 공통으로 줄일 수 있다. 적은 병력을 화면에 가득 차도록 확대하지는 않는다. 장수별 이름·잔여 병력·상태는 실제 장수 하나당 하나의 표시를 유지하며, 화면용 병사 구획을 새 군대로 계산하지 않는다.

## 검수와 재현

`npm test` **677개 모두 통과**, `npm run check` JavaScript **366개** 구문 검사 통과, `npm run release` 단일 HTML 생성 완료. 실제 단일 HTML에서도 네트워크를 끈 상태로 역사 불러오기·설정 저장·전술 켜기/끄기·8지휘관 병사 그리기/깊이 순서·지도 복귀까지 확인했고 페이지 오류는 없었다. [실행본 전술창](v58-recording-on.png), [녹화 선택](v58-recording-choice.png).

실제 Chromium에서 제작된 전장 계획을 기존 캔버스 렌더러로 연속 재생했다. 세 경우 모두 겹침0, 접촉 중 실제 좌표 이동, 정확한 최종 병력을 확인했다. 병사 전체 몸체의 겹침은 대기/진격/교전/후퇴 및 이동 틱 사이까지83ms 간격으로 검사했다. 순수 표본 검사와 실제 브라우저 재생을 함께 사용했다.

| 표시 검수 조건 | 시작 병사 그림 합계 | 동시에 교전한 접촉면 | 기본 연출 시간 |
| --- | ---: | ---: | ---: |
| 1만:1만 | 16 | 1 | 9.68초 |
| 5지휘관5만:3지휘관30만 | 280 | 5 | 29.84초 |
| 15지휘관60만:1지휘관1만 | 488 | 2 | 43.44초 |

이는 기본 시간이며 브라우저 연속 재생은 실제2배속으로 수행했다. 60만 단일 지휘관 등은 표시 검증용 자료다. 실제 지휘한도·게임 판정을 늘리거나 이러한 결과를 실제 시뮬레이션 역사라고 제시하지 않는다. [브라우저 결과](v58-browser-results.json)에는 각 장수의 최종 병력과 기대값, 페이지 오류 목록을 보관했다. 그림은 [5대3 교전](v58-tactics/five-contact.jpg), [15대1 교전](v58-tactics/fifteen-contact.jpg)에서 확인할 수 있다. 연속 재생 영상은 개발 작업물 `.artifacts/v58/*-continuous.webm`에 남겼으며 실행 파일에는 넣지 않는다.

관련 검사에는 원본 손실의 교전별 합계, 전사 후 정지/공격 금지, 무방비 진입, 역공·추가 진격·왕 방어, 점령 후 재탈환, 일시정지/시점 탐색/같은 시드 재생, 고정 전장 높이와 실제32지휘관 기록을 포함한다. 8개 시드의96개 국가 차례/32개 집단전에서 기존 게임 상태·난수 결과가 일치했다. 보호 파일 해시와42개 기존 지도 장면 스냅샷도 대조한다. 이전에 개별 교전마다 순차 접근을 요구하던 검사는 공통 전장과 원래 순서의 결과 공개를 검사하도록 변경했다.

```sh
npm test
npm run check
npm run release
node tests/make-v58-demos.mjs
python tests/tactical_v58_visual.py
python tests/selected_battle_v58_smoke.py
```

브라우저 검사는 Python Playwright와 로컬 Chromium이 있는 개발 환경에서 실행한다. 실행용 HTML에는 이 도구가 필요 없다. `selected_battle_v58_smoke.py`는 실제 단일 HTML에서 역사 파일 불러오기, 선택 저장, 전술화면을 끈 지도 후퇴/점령, 다시 켠 전술화면을 네트워크 없이 검사한다.

이 검수는 모든 지도·장수 배치의 연출 품질이나 모든 기기의 성능을 보증하지 않는다. 확인된3조건과 기존 실제 전투 기록에서 표시 수량·경로·손실·결과의 일치를 검증했다. 일반 단일 HTML만 배포하며 별도 모바일판은 만들지 않는다.
