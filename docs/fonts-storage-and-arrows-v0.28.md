# 글꼴·저장 용량 확인과 화살표 개선안

확인일:2026-10-26. 현재v0.28 소스 기준이며,아래3번은 구현 변경이 아닌 제안이다.

## 1. 글꼴과 상업 영상

현재`assets/`에TTF/OTF/WOFF/WOFF2 파일이 없고,런타임에`@font-face`·폰트 데이터 내장·Google Fonts 등 외부 폰트 다운로드가 없다. CSS에 글꼴 이름을 지정하고,PC에 설치된 글꼴을 순서대로 사용한다. 따라서 사용자 PC마다 실제 선택되는 글꼴이 다를 수 있다. CSS에 이름이 있다는 것과 해당 글꼴 파일을 제품 안에 넣어 배포하는 것은 다르다.

| 글꼴 | 소스에서의 용도 | 확인한 범위 |
|---|---|---|
|Pretendard|화면 본문 우선 후보|공식 SIL Open Font License1.1 원문 확인. 상업적 영상·이미지·문서 제작 허용.|
|Noto Sans KR|본문 대체 후보|공식 OFL1.1 원문 확인. 상업적 결과물 제작 허용.|
|Noto Serif KR|일부 제목 후보|공식 OFL1.1 원문 확인. 상업적 결과물 제작 허용.|
|Malgun Gothic·Batang·Segoe UI·Georgia 및 시스템 기본/고정폭 글꼴|지도 상태 글자·제목·OS 대체 글꼴|현재 앱에서 파일을 추출하거나 묶어 재배포하지 않음. 사용자 OS의 설치/사용 권한과 폰트 파일의 별도 배포/내장 권한은 구분해야 함.|

확인한 OFL은 무료 사용·내장·수정·재배포를 허용하되,폰트 자체의 단독 판매 금지·배포 시 저작권과 라이선스 보존·수정 글꼴의 예약 이름 조건 등이 있다. **폰트로 만든 일반 문서·이미지·영상 결과물이 OFL을 따라야 한다는 뜻은 아니다.** 상업적 유튜브 콘텐츠 제작은 이들 오픈 폰트의 허용 범위에 해당한다.

원문:

- [Pretendard 공식 라이선스](https://github.com/orioncactus/pretendard/blob/main/LICENSE)
- [Noto Sans KR 공식 OFL](https://github.com/google/fonts/blob/main/ofl/notosanskr/OFL.txt)
- [Noto Serif KR 공식 OFL](https://github.com/google/fonts/blob/main/ofl/notoserifkr/OFL.txt)
- [Microsoft 공식 폰트 사용 FAQ](https://learn.microsoft.com/en-us/typography/fonts/font-faq)

이번 환경에서는 Microsoft FAQ 원문 접속이 차단되어 Windows 각 글꼴의 개별 약관까지 직접 대조하지 못했다. 따라서 모든 사용자 PC의 모든 대체 폰트에 대해 무조건적인 상업 이용 보증을 한 것은 아니다. **상업 영상용 글꼴을 확실하게 통일하려면 OFL이 확인된 Pretendard/Noto로 지정·설치하거나,후속 작업에서 라이선스와 함께 내장하는 방식이 가장 명확하다.** 이번 작업에서는 전역 글꼴을 임의 변경하거나 새 폰트 파일을 포함하지 않았다.

## 2. 저장·불러오기는 완전 무제한이 아님

| 기능 | 실제 현재 동작 |
|---|---|
|세계 JSON 불러오기|파일5MiB 이하와 문자열5×1024×1024자 이하를 각각 검사. 초과 시 거부.|
|세계 JSON 내보내기|앱이 정한 파일 크기 상한은 없음. 국가·인물·영토·규칙·지도 설정을 저장. 진행 중 경기 전체 저장과 다름.|
|전체 역사 내보내기|앱이 정한 파일 크기 상한/턴 상한은 없음. 시작 세계·시드·전체 기록·결과·최종 표시 세계를 JSON으로 생성. 브라우저 메모리·디스크 한계는 있음.|
|내보낸 역사/진행 파일 가져오기|현재 UI에는 없음. ‘불러오기’는 세계 설정 JSON용. 내보낸 역사 JSON을 읽어 경기를 재개하는 기능은 후속 작업임.|
|현재 경기 자동 저장/복원|작으면 localStorage,512Ki문자 초과/300기록 초과/작은 저장소 쓰기 실패면 IndexedDB128기록 단위로 전환. 고정 게임 턴 상한은 없지만 브라우저 저장 할당량·남은 디스크·시크릿 모드 제한은 있음.|

브라우저 자동 저장은 HTML을 연 주소/경로와 브라우저 프로필에 종속된다. 다른 브라우저/파일 경로/기기에서 자동 저장이 그대로 보이는 것을 보장하지 않는다. 이번 요청은 제한 확인이므로5MB 제한 제거·외부 진행 세이브 가져오기 같은 별도 기능을 임의로 추가하지 않았다.

## 3. 국경 화살표: 현재 원인과 개선안

현재`round-campaign.js`가 같은 계절의 모든 국가 차례를 모아 실제 출정·수비 이동·공격·후퇴를 남긴다. `campaign-routes.js`는 **동일 인물·동일 방향·동일 전체 경로**의 반복만 묶는다. 다른 장수의 겹치는 구간은 개별 선을 보존하고,`operation-geometry.js`가 공유 구간을 옆으로 벌린다. 왕복·여러 장수·공격과 후퇴가 겹치면 선이 금방 늘어난다.

권장안은 **전선 보기 / 전체 경로 보기** 두 단계다.

1. 기본 전선 보기에서는 **같은 국가·같은 진행 방향·같은 통과 구간**의 화살표를 하나로 묶고 ‘3개 부대’처럼 참여 수를 표시한다. 한 장수의 반복 진격을3개 부대로 잘못 세지 않도록 고유 인물/생애를 구분한다.
2. 공격·방어 이동·후퇴·반대 방향은 같은 선으로 합치지 않는다. 후퇴는 자국 쪽 별도 통로로 빼며 현재의 국가색과 선 모양을 유지한다.
3. 현재 움직이는 장수와 현재 전투의 경로를 앞에 그린다. 장수 카드를 선택하면 그 장수의 개별 경로를 펼친다. 선택을 풀면 다시 묶는다.
4. 전체 경로 보기는 지금처럼 계절 전체의 개별 경로를 볼 수 있게 남긴다. 기록이나 계절 전투 흔적을 삭제해서 단순하게 만들지 않는다.
5. 병력에 따른 굵기는 유지하되,통합선에 여러 전투의 병력을 중복 합산해 가짜 총병력을 표시하지 않는다. 참여 부대 수와 경로 통합을 우선하고,정확한 부대 병력은 선택 시 표시한다.

먼저 ‘겹치는 구간 묶기+선택 시 펼치기’를 적용하는 작은 패치가 적절하다. 자유로운 지도 경계와 실제 인접/병력/이동/전투/RNG는 바꾸지 않는 화면 전용 작업이다. **이번v0.28에서는 이 화살표 개편을 구현하지 않았다.**
