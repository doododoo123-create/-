# 구조 · Studio v0.12.0 / 첨부160영토와 세계별 규모 규칙

## 데이터와 엔진

`편집 세계 → validateWorld → createRun → v11-core.prepareTurn → engineState + 사건 → 화면 상태 → TurnPlayback`

세계 형식은 `schemaVersion:2`입니다. 국가·인물·영토는 문자열 ID로 연결합니다. `mapKind:v11`은 원본 80영토의 순서 있는 인접 그래프·형상·수도를 사용합니다. `mapKind:grid`는 사용자 지정 크기와 상하좌우 인접 그래프를 사용합니다. `mapKind:free`는 영토 ID별 자유 다각형과 명시적 연결을 사용하며 행·열/영토 수가 독립적입니다. 미배정 영토는 편집 중 허용하고 경기 시작 시 거부합니다. 국왕·승상은 국가당 하나, 장군 자리는 같은 국가에서 중복할 수 없습니다.

`data/v11-preset.js`는 사용자 HTML에서 추출한 지도·7국·명부 데이터입니다. 보존한 원본 파일은 런타임에 읽지 않습니다. 원본 예제의 초기 상태는 원본과 같고 지도·국가·인물·규칙은 편집 데이터로 주입합니다. 장군은 영토 수에 따라 생성·활성화됩니다. 이름 있는 후보 장군이 부임할 자리가 생기면 그 설정을 사용합니다.

`engine/v11-core.js`는 원본 계산을 팩터리 함수로 분리한 것입니다. 알고리즘 순서와 숫자 인덱스 상태는 원본 그대로 보존했습니다. 지도, 국가/명부, 초기 병력과 규칙만 인자로 받습니다. 기본 규칙을 바꾸기 전에 원본 대조 테스트를 확인해야 합니다. UI용 문자열 ID 처리는 `simulation.js`가 맡으므로 핵심 계산에 UI 코드가 들어가지 않습니다. 원본과의 비교 기반을 유지하며 필요할 때 생산·전투·인사 함수를 더 나눌 수 있습니다.

`simulation.js`의 `initialWorld`는 검증한 시작 세계 복사본, `engineState`는 권위 있는 원본 형식 상태, `world`는 표시용 파생 상태입니다. 화면의 병력·장군·주둔지·영토 담당자는 항상 `engineState`에서 계산합니다. 국가 총병력과 수도 예비병, 개별 장군 병력을 구분합니다. 문자열 시드 해시를 사용하지 않고 32비트 정수 시드를 원본 LCG에 직접 전달합니다. 예전 `random.js`는 호환 소스이며 현재 엔진에서는 사용하지 않습니다.

## 기록과 연출

엔진은 한 국가 턴을 한 번 계산합니다. 모든 원본 사건과 주사위·시도·장군별 전투를 정규화해 기록합니다. 원본 사건의 중간 스냅샷을 `frames`로 연결하고, 화면은 현재 사건의 이전/이후 상태만 표시합니다. 승패 설명 후 `apply` 장면에서 지도에 병력과 점령을 반영합니다. 공격 점수는 방어 주사위 동안 남습니다. 후임·충원·전사·생산도 별도 장면입니다.

`TurnPlayback`은 자체 시계만 사용합니다. 연출·배속·정지·건너뛰기는 게임 난수를 소비하지 않습니다. 한 단계는 판정 묶음을 자동으로 보여주고 멈추며, 공격·방어·손실 반영은 한 묶음입니다. 원래 눈금 → 보정 합치기 → 최종값을 같은 주사위에 보여줍니다. 전체 턴 기록과 종료 배너는 턴이 완료될 때 공개합니다.

중간 프레임은 최신 턴과 제한된 재생 캐시에만 열거 불가능한 속성으로 유지하고 저장하지 않습니다. 과거 기록은 전체 작은 사건과 전투 데이터로 유지합니다. 엔진 내 최근 기록 중복도 제거합니다. 진행 중 연출에서 새로고침하면 마지막 완료 턴부터 같은 난수로 다시 계산합니다. 과거 턴은 별도 실행을 복원하고 저장된 판정을 대조해 재생합니다.

## 저장

세계 파일: `{kind:'saguk-studio-world',version:2,world}`. 버전 1도 읽어 스키마 2로 변환합니다. 이전 편집 이름·소유권·초상화를 보존하고 단순 규칙을 v11 기본값으로 교체합니다. 기존 내장 세계는 원본 지도 및 후보 명부를 복원합니다. `saguk-studio.world.v1` 키를 계속 사용하며 이전 원본은 `.before-v11` 키에 백업합니다.

완료 턴 저장: `{kind:'saguk-studio-run',version:1,engineVersion:'studio-v11-18',seed,initialWorld,engineState,history}`. 키는 `saguk-studio.completed-run.v11`입니다. 매 턴 연출 완료/건너뛰기 때만 저장합니다. 복구 시 원본 상태 검증, 시드 일치, 턴 기록 수와 판정을 검사합니다. 새 세계/세계 가져오기는 진행을 비웁니다. 새 실행과 재현은 초기 상태를 저장합니다.

역사 내보내기는 시작 세계·전체 기록·최종 상태를 별도 JSON으로 보관합니다. 역사 가져오기는 아직 없습니다. 데이터는 외부로 전송하지 않습니다. 저장 용량 부족은 화면으로 알리고 파일 내보내기를 안내합니다.

## 화면·배포·확장

`atlas-view.js`는 원본 다각형·국경·장군 담당구역·실제 주둔군을 그립니다. 사용자 격자에는 `map-geometry.js`를 사용합니다. 장수 50종·새 왕/승상 20종과 이전 호환 초상화는 내장 이미지로 인터넷 요청 없이 동작합니다. 사용자 문자열은 이스케이프합니다.

`app.js`는 편집·조작·저장·연출 연결만 맡습니다. 시작 세계와 실행을 분리하여 편집이 현재 실행에 끼어들지 않게 합니다. 관리자 개입은 이후 검증된 상태 변경과 별도 사건으로 추가합니다.

Node 기본 HTTP 서버와 ES 모듈로 개발합니다. `npm run release`가 로컬 모듈과 CSS·이미지를 합쳐 `dist/사국쟁패 Studio.html`과 추적하는 루트 실행본을 만듭니다. 원본 소스는 `src/`이며 생성 HTML을 직접 수정하지 않습니다. Windows 앱은 UI·엔진을 감싸고 저장 어댑터를 교체하는 방향으로 확장합니다.

게임 규칙 변경은 원본 비교·경계 조건을, 저장 변경은 이전 파일과 복구를, 화면 변경은 현재 부대와 중간 상태·좁은 화면·단일 실행본을 검증합니다. 주요 변경은 Git 커밋과 태그로 남깁니다.

## v0.2.1 지도 전체화면과 주사위 색

`ui/map-stage.js`는 현재 `playback.displayWorld`와 동일한 `renderAtlas`·`renderArena`를 조합합니다. 지도·간단한 오른쪽 판정·국가 현황·조작부를 한 화면에 표시하며 미래 턴 기록은 숨깁니다. 기본 판정 화면의 버튼은 재출력하지 않고 아래 공용 조작부를 사용합니다. 작은 높이에서는 중복 계산 설명을 줄이고 최근 기록보다 현재 판정을 우선합니다. 표시 전용 스타일은 `map-stage.css`에 분리했습니다.

브라우저 전체화면의 대상은 다시 만들지 않는 `#app`입니다. 내부 장면을 갱신해도 전체화면이 유지됩니다. 닫기·Esc·브라우저의 전체화면 종료를 동기화하며, API 미지원/거부 시에도 고정 화면 배치를 유지합니다. 전체화면 전환은 엔진·난수를 호출하거나 연출 시계를 초기화하지 않습니다.

`ui/dice-colors.js`는 면 수 대비 표시 숫자를 밝은 색부터 빨강까지 연결합니다. 보정 후 범위를 넘는 숫자는 그대로 두고 색상 강도만 제한합니다. 굴림은 게임 난수와 무관한 장식 숫자를 사용하고, 각 숫자와 색을 같은 CSS 프레임에 지정합니다. 미공개 숫자의 색은 중립색으로 유지합니다.

단일 HTML 빌드에는 새 모듈과 `map-stage.css`를 함께 넣습니다. 독립 실행본에서도 외부 이미지나 스타일 요청이 필요하지 않습니다.

## v0.2.2 지도 단독 화면과 일시적인 중앙 판정

`map-stage.js`는 지도와 `judgment-overlay.js`만 조합합니다. 고정 우측 패널·상태 제목·국가 집계·조작부는 없습니다. Space/Enter/A/S/Esc가 기존 진행 액션을 호출합니다. 전체화면을 담당하는 `#app`은 유지하며 내부만 다시 그립니다. 단축키 안내와 배속 설정은 일반 화면에 둡니다.

중앙 연출은 원본 HTML의 작은 어두운 박스·인물·특성·주사위 배치를 따릅니다. 공격 확정값은 수비 굴림 동안 남고, 전사 판정은 대상 인물의 별도 판정입니다. 대기·지도 반영·턴 완료 때 중앙 창을 출력하지 않습니다. `die-view.js`는 기존 `arena-view.js`와 중앙 창이 함께 사용하는 주사위 컴포넌트이며 높은 값의 붉은 색상과 보정 수치를 보존합니다.

기록된 스냅샷을 가진 사건은 설명/판정 장면에서 이전 상태를 유지합니다. 결과 뒤 `departing` 240ms 동안 창 전체가 퇴장하고, 다음 `apply`에서 이후 상태를 표시하며 1800ms 동안 지도 효과를 읽을 수 있습니다. 두 시간은 배속에 따릅니다. 수동 묶음이 완료되면 `settled`로 표시해 변화 문구와 경로를 비우고 지도만 남깁니다. 일시정지 도중의 중앙 창과 효과는 읽을 수 있게 표시합니다. 이 전환은 게임 난수나 엔진을 다시 호출하지 않습니다.

`map-effects.js`는 같은 사건의 `worldBefore`/`worldAfter`에서 수도 예비병·각 장군 병력·충원력·보급·지휘한도·생사/세대·수도와 소유권 차이를 계산합니다. 번호와 국가로 장군을 연결하므로 후임의 문자열 ID가 달라도 대응합니다. 사라진 부대는 이전 주둔지를 효과 위치로 사용할 수 있습니다. 소멸한 고립 생산을 가짜 증가로 더하지 않습니다.

`atlas-view.js`는 실제 부대/수도 카드 위에 변화 배지를 놓고 점령 영토를 강조합니다. 군대 변화와 강화는 색·문구로 구분하고, 현재 사건의 영토 변화만 표시합니다. 점령 문구는 부대 변화 배지와 겹치지 않는 가까운 위치를 우선하며 영토까지 선으로 연결합니다. 효과 자료는 파생 표시 데이터이며 저장이나 엔진 상태에 추가하지 않습니다.


## v0.3.0 삽화 지도와 편집

세계 스키마 2에 선택적인 `cartography:{version:1,style,opacity,background,polygons,links}`를 추가합니다. 없는 기존 파일은 종전과 동일하게 검증하고, 화면의 기본 삽화 스타일만 적용합니다. `polygons`는 영토 문자열 ID별 `{points:[[x,y],...],center:[x,y]}`이며 고정 1200×800 표시 좌표입니다. 위치는 실제 다각형 내부를 검증하고, 자기 교차·중복 점·잘못된 좌표를 거부합니다. `background`는 길이 제한이 있는 PNG/JPEG/WebP data URL만 받으며 SVG·외부 URL은 허용하지 않습니다. 업로드 그림은 브라우저에서 비율을 유지해 최대 3840×2560 WebP로 저장하고 기존 내장 이미지는 가능한 한 재압축하지 않습니다.

`model/cartography.js`는 검증과 다각형 연산, `ui/cartography-geometry.js`는 원본/격자 형상에 저장된 경계를 덮어쓰고 공유 모서리로 국경을 그립니다. `ui/map-editor.js`는 작성 중 경계, 좌표 변환, 드래그, 적용·취소, 12단계 되돌리기(국가·인물 등 다른 정보 변경 시 초기화), 인접 연결, 이미지 읽기를 담당합니다. 적용 전에는 기존 세계를 변경하지 않습니다. 꼭짓점 이동은 기존에 같은 좌표를 공유한 이웃 영토에도 적용합니다. 새로 그린 다른 영토끼리의 겹침은 자동 정리하지 않습니다. 격자 편집은 별도 선택지로 유지합니다.

`links:null`은 기존 원본/격자 인접 관계입니다. 명시적인 배열이 있으면 그것을 권위 있는 양방향 인접 그래프로 사용합니다. `neighbors`와 `engineFor`가 동일한 연결을 사용하도록 어댑터에서 원본 atlas의 neighbors만 주입합니다. 기본 그래프, v11 핵심 계산, 난수 알고리즘은 바꾸지 않았습니다. 그림과 경계만 바꾸었을 때 24턴의 전체 엔진 상태·사건·난수가 일치하는 검사를 추가했습니다. 인접 편집은 지리 자체를 바꾸는 설정으로 새 실행의 공격·보급 경로에 영향을 줍니다.

삽화는 사용자 참고 이미지의 분위기를 바탕으로 생성한 지형 판을 `data/terrain-art.js`에 JPEG로 내장하고 현재 대륙 외곽에 잘라 표시합니다. 전체화면·일반 관찰·편집·중간 재생 프레임은 동일한 `geometryFor`를 사용합니다. 이미지나 경계 정보는 게임 난수를 소비하지 않습니다. 배포 빌드는 지도 편집 CSS와 삽화도 단일 HTML에 포함합니다. 기존 저장 형식과 원본 비교 검사는 유지합니다.


## v0.3.1 칠목과 청동 UI

사용자가 제공한 77종 UI 모음집에서 주요 아트 8개는 비율·투명도를 유지한 WebP로, 나머지 69개 디자인은 SVG로 `assets/ui-kit/`에 보관합니다. 원본 안내는 SOURCE-NOTES.md이며 적용 방식은 해당 폴더 README.md에 기록했습니다. 외부 서비스나 별도 이미지 폴더 없이 실행할 수 있도록 배포 HTML에 실제 사용 자원을 내장합니다.

`ui/lacquer-bronze.css`는 마지막에 로드하는 표시 전용 스타일입니다. CSS 변수에 이미지를 한 번 선언해 반복 사용합니다. 버튼은 border-image의 모서리 조각을 유지하며 기본/호버/눌림/비활성 이미지를 전환합니다. 인물 프레임은 실제 초상 위에 클릭을 가로막지 않는 장식 레이어로 얹고, 지도 프레임은 일반/편집 화면에만 표시합니다. 녹화용 지도 전체화면에는 프레임이나 고정 패널을 추가하지 않습니다.

`ui/kit-icons.js`는 `scripts/ui-kit.mjs`가 빌드 때 원본 SVG에서 동기화하는 정적 경로입니다. 스크립트·외부 이미지·외부 참조를 거부하며 색상은 기존 아이콘 호출의 currentColor를 따릅니다. 아이콘 별칭은 icons.js에 있어 기존 기능의 호출은 유지합니다. 육각 주사위는 빈 프레임 위에 기존 동적 숫자·난수와 무관한 회전 연출을 그대로 표시합니다. 10 초과 보정과 빨강 강도도 기존 모듈을 사용합니다.

빌드는 로컬 UI CSS의 자원 URL을 data URL로 바꾸고 CSS·인라인 아이콘을 단일 HTML에 넣습니다. 개발 서버는 WebP 이미지 형식을 제공합니다. 세계 형식·엔진 버전·난수·저장 형식은 이 변경에서 바꾸지 않습니다.


## v0.3.2 초상화와 전투 지도

사용자가 제공한 `장수_초상화_50명_경량.zip`의 50개 JPG는 비율을 유지한 288×432 WebP로 압축해 assets/portraits/에 보관합니다. 원본 특징 목록은 선택 안내로만 사용합니다. scripts/general-portraits.mjs가 빌드에서 data URL과 안내 문구를 src/data/general-portraits.js로 동기화합니다. 세계에는 이미지 대신 `portraitKey:general-001`~`general-050`만 저장하고 이전 키도 읽습니다. 새 이미지 선택 허용 목록만 확장하며 스키마와 엔진 버전은 유지합니다.

portraits.js는 명시적인 선택을 우선하고, 원본 장군 35명은 국가·자리에서 서로 다른 사진을 정합니다. 새 인물·후임은 안정된 ID에서 배정하므로 게임 난수를 소비하지 않습니다. 이전의 장군 기본 사진 키는 새 기본 사진으로 표시합니다. 기존 국왕·승상 이미지와 직접 선택한 지도자 사진은 계속 사용할 수 있습니다. 지도 얼굴 확대는 CSS로 표시하며 이미지 파일의 얼굴 자체를 변경하지 않습니다.

unit-layout.js는 표시할 카드 중심만 배치합니다. 카드 크기 52×90, 가까운 후보의 겹침과 이동 거리를 비교하고 실제 영토 중심까지 연결선을 둡니다. 영토/주둔지 ID와 전투 후보는 수정하지 않습니다. map-effects는 새 카드 위에 실제 변화 문구를 놓습니다. 지도 마커는 그림·이름·병력 세 요소만 상시 표시하고 나머지는 툴팁에 둡니다.

battle-map.js는 카드 바깥에서 시작하는 양측 경로와 14px 화살촉, 카드에 가리지 않는 근처 전투 표식을 그립니다. 실제 전투 위치와 표식을 연결합니다. map-ocean.js는 해안의 얕은 색과 내장 바다 자원을 제공하고, 바다 사진 한 장이 SVG 아래 전체 관찰 화면을 채웁니다. 이 방식으로 화면 비율이 달라도 바다의 사각 이음선이 나타나지 않습니다. 사용자 배경은 덮어쓰지 않습니다.

display-names.js는 후임 인물의 `·자리대세대`를 이름에서 숨기고 표시용 사건 문구도 정리합니다. 원본 엔진의 이름 생성·후임 식별자·사건 저장과 숫자 계산은 변경하지 않습니다. 정상 판정과 재현 비교는 원본 형식 그대로 수행합니다. 표시 처리는 문자열을 반환하며 UI에 넣을 때 기존 이스케이프를 계속 사용합니다.

map-refinements.css는 마지막에 로드해 세로 카드·얼굴 크기·전투 경로·지도 주사위의 세로 정렬을 담당합니다. 일반/전체화면 지도는 동일한 마커와 자원을 사용합니다. 후속 UI 수정은 이 파일들과 공용 표시 함수에서 수행합니다.

- `ui/map-generator.js`는 독립 dialog에서 이미지 압축·canvas 보정·섬 선택·분할·적용을 처리합니다. 작업 중 입력을 잠그고 취소/이미지 교체의 오래된 비동기 응답을 무시합니다. DOM에는 사용자 이미지 코드를 삽입하지 않고 압축한 PNG/JPEG/WebP 픽셀만 사용합니다.
- `designedBorders`는 동일 모서리를 먼저 합치고 긴/짧은 공선 모서리를 나누어 중복/가짜 국경을 막습니다. 렌더러는 같은 소유국의 선을 한 path로 합쳐 자동 생성 지도에 수천 개의 장식 노드가 생기지 않게 합니다.
- `ui/map-camera.js`는 overview/editor/simulation별 SVG viewBox 상태를 관리합니다. 휠 기준점 확대(50~500%), 버튼·원위치·우/가운데 드래그와 편집 이동 모드를 제공합니다. 지도/장면 렌더 뒤 viewBox를 복구하며 정규 영토 좌표·세계 저장·난수와 독립적입니다. 편집 좌표는 기존 화면→SVG 변환을 사용합니다.
- 모든 atlas-scroll 위의 지도 프레임 덮개를 제거했습니다. 전체화면에는 카메라 고정 버튼을 넣지 않고 휠·드래그·＋/−/0을 사용합니다.

## v0.7.0 D30·승리 성장·산악

`model/combat-rules.js`는 순수 함수로 병력 배율 보정, 장군·전적·지형 보정, 점수 차 등급, 적은 부대 기준 손실과 1명 단위 반올림을 계산합니다. `rules.battleMode:additive30`만 새 계산을 사용하며 v11 분기·난수 소비 순서는 원본 대조로 유지합니다. 현대 전투만 장군 `wins`를 만들고 실전 승자에게 1을 더합니다. 후임은 0으로 초기화합니다. 국왕·승상·전사·후임은 D10을 유지합니다.

엔진은 만 단위를 사용하되 현대 병력은 소수 넷째 자리까지 보존합니다. 생산·회수·배분·총병력 합산도 같은 정밀도로 정규화하고 분배 마지막 조각이 지휘한도를 넘지 않도록 합니다. 기존 v11은 정수 병력·기존 손실·최대 3영토 점령을 유지합니다. 새 점령 기준은 기본 8/16점 차입니다. 손실·보정 표는 세계 규칙 데이터이며 `ui/rules-view.js`에서 편집합니다.

실행 버전은 `studio-v11-13`입니다. restoreRun은 11/12의 초기 세계를 원본 v11로 고정하고 11의 해상 보급도 끕니다. 편집 세계는 새 규칙으로 새 실행할 수 있지만 진행 중 실행은 초기 규칙을 계속 사용합니다. 원본 예제는 battleMode:v11을 명시합니다.

## v0.7.0 과거 턴 재생

`engine/replay.js`는 initialWorld·seed와 기록된 controls로 독립 실행을 재구성합니다. 매 턴 주사위·양측 최종 점수·손실·점령·영토 변화를 기존 기록과 대조하고 다르면 중단합니다. DOM이나 저장 API를 사용하지 않습니다. 매 20턴 화면 제어를 양보하고, 중간 체크포인트와 최근 8개의 선택 턴 프레임을 캐시합니다. 일반 진행은 이전 프레임을 버리고 완료 턴의 작은 기록만 보관합니다.

## v0.12.0 첨부 SVG와160영토 규모

`assets/maps/continent_160.original.svg`와`docs/reference/continent_160.html`은 첨부 원본입니다. `scripts/import-continent160.py`(Python 표준 라이브러리)는 XML/JSON 메타데이터와 M/L/Z 경계만 읽어`continent160-map.js`를 만듭니다. 원본 스크립트·인터랙티브 레이어·스타일은 실행하지 않으며, 정적 SVG artwork에서는 제거합니다. 영토154의 연속 중복 꼭짓점1개만 제거하고 나머지 경계를 균일 변환합니다. 인접 관계는 첨부의357개 양방향 목록입니다. 이 지도에서만 아주 짧은 공유 경계도0.1좌표 단위부터 인정해 자동 재계산/원상복구도357개와 일치하며 기존 지도의0.8기준은 유지합니다.

`continent160-layout.js`는 실제 연결 그래프와 기존 수도 방향·영토 비율을 사용해 국가를 결정론적으로 재배정하고 경계 셀을 조정할 때 국가 연결을 보존합니다. 게임 난수를 소비하지 않습니다. 새 지도 적용은 국가/인물을 보존하되 초기 영토/소유권을 교체하며 MapEditor의 전체 세계 undo에 포함됩니다. 기본 진입은createContinent160World, 기존loadWorld/loadRun이 있으면 자동 교체하지 않습니다. 새 실행에서만 편집 세계를 사용합니다.

`map-scale.js`는 명시 설정(기본4/1/1/false,160용8/2/1.5/true)과 정수 생산·거리·수도 예비병 목표를 관리합니다. command-regions.js의 제한된 연결 성장으로8칸 구역을 만들고 기존4칸 열거 루프는 그대로 둡니다. 소국이 영토를 수복해 예비병 목표가 올라갈 때 기존 병력을 회수하지 않으므로 validation은 적응형 규칙의 최소 보호선과 현재 배분 목표를 구분합니다. 회복 이후 생산은 새 목표를 먼저 채웁니다.

engine18은17 저장의 지휘한도/손실/home 복귀를 그대로 보존하고 새 규모 설정만 원래값으로 고정합니다.16 이하의 이전 호환 분기는 유지합니다.80영토 저장과160영토 저장 모두 별도 엔진 캐시·세계 정의에서 재구성하여 같은 난수와 기록을 보존합니다.
