# 구조와 향후 수정 지점

## 데이터 흐름

`편집 화면 → validateWorld → 시작 세계 → createRun(복사본, 시드) → nextTurn → 상태·사건 → 관찰 화면`

세계 데이터는 `schemaVersion: 1`이다. 국가·인물·영토는 문자열 ID로 연결하며 화면 순서나 국가 수를 식별자로 사용하지 않는다. 영토 소유국과 인물 소속은 `null`일 수 있다. 국가는 병력·추가 충원·색·성향을, 인물은 직책·능력·성향을 보유한다. 영토는 ID·행/열·이름·소유국을 가진다. 규칙은 별도 `rules` 객체다.

국왕과 승상은 국가당 각 1명만 허용하고 장군 수는 자유다. 새 국가를 만들 때 왕이나 장군을 억지로 생성하지 않는다. 직책이 비어 있으면 기본 보정 0과 국가 성향으로 실행한다. 국가 삭제는 영토를 무주지로, 인물을 무소속으로 바꾸어 인물 데이터를 보존한다.

## 모듈 책임

- `model/world.js`: 스키마, 참조 무결성·숫자·색상·중복 검증, 상하좌우 인접 관계, 기본 규칙과 순수 데이터 변경.
- `data/demo-world.js`: 사용자 원본에서 가져온 샘플만 담는다. 엔진은 이 모듈을 알지 못한다.
- `engine/random.js`: 문자열 시드 해시와 32비트 LCG. 게임 판정에 `Math.random()`을 쓰지 않는다.
- `engine/simulation.js`: `createRun`, `nextTurn`, `currentActor`, 전투·생산·종료 판정. DOM, 저장, 타이머를 알지 못한다. 실행 엔진 버전은 `studio-0.1`.
- `storage/world-store.js`: 버전 있는 세계 JSON, 브라우저 저장, 파일 내보내기. 잘못된 입력은 상태에 넣기 전에 거부한다.
- `app.js`: 6개 화면의 조립·폼·이벤트·타이머를 연결한다. 규칙 수식과 저장 형식은 해당 모듈에 위임한다. 이 단계에서는 파일 분할을 과도하게 늘리지 않으며 화면이 커지면 화면별 `ui/views/`로 옮긴다.
- `ui/style.css`, `ui/icons.js`: 시각 스타일·공용 아이콘·문자열 이스케이프. 인물 초상화는 이미지 대신 이름 기반 자리 표시를 사용한다.

## 시작 세계와 실행의 분리

`createRun`은 검증한 세계의 복사본을 만들고, 원본을 `initialWorld`로 보존한다. 실행에는 시드·현재 난수·턴·라운드·행동 순서·기록·결과가 있다. 영토가 없는 국가는 참가하지 않고 실행 복사본의 병력은 0이 된다. 시작 세계는 그대로 남는다.

`nextTurn`은 이전 실행을 수정하지 않고 다음 상태를 반환한다. 변경되는 세계·순서 배열을 복사하며 과거 사건은 불변으로 취급한다. 화면 타이머는 엔진을 한 턴씩 호출할 뿐이다. 화면 변경·배속·일시정지는 판정 난수에 관여하지 않는다. 앱이 숨겨지거나 다른 메뉴로 이동하면 자동 진행을 멈춘다.

기록은 화면용 문장 외에 주사위 원값·면 수, 전투 점수와 양측 시작 병력·손실, 소유권 이전, 생산, 멸망과 종료 결과를 보유한다. 지금은 턴 단위 기록을 내보내는 것까지만 지원한다. 재생·분기에는 이후 상태 스냅샷/사건 적용기·기록 로더를 추가하고 과거 파일과의 버전 호환 정책을 정해야 한다.

## 저장 경계

세계 파일: `{ kind: 'saguk-studio-world', version: 1, world }`.

역사 파일: `{ kind: 'saguk-studio-history', engineVersion, seed, world, history, result, finalWorld }`. `world`는 시작 상태다. 재생/가져오기를 구현하지 않았으며 세계 파일 로더는 이를 거부한다.

브라우저에는 시작 세계만 `saguk-studio.world.v1` 키로 저장한다. 네트워크로 데이터를 보내지 않는다. 손상된 저장값을 읽을 수 없으면 예제 세계를 보여주고 오류를 알리며 시작 시점에는 손상된 값을 자동으로 덮어쓰지 않는다. 사용자가 편집하거나 저장을 선택하면 새 세계를 저장한다. 브라우저 저장 실패 시 파일 내보내기를 안내한다.

## 실행과 배포

개발 모드는 Node 기본 HTTP 서버와 ES 모듈이다. 설치 의존성이 없어 잠금 파일은 필요 없다. 서버는 숨김 경로와 작업 루트 밖 경로를 거부하고 127.0.0.1에만 바인딩한다.

`npm run build`는 로컬 이름 가져오기/직접 이름 내보내기만 지원하는 작은 빌드 스크립트로, 모듈을 의존 순서로 합치고 CSS·아이콘을 넣어 단일 HTML을 만든다. 권위 있는 코드는 항상 `src/`다. 향후 import 문법이나 외부 라이브러리를 추가하면 번들러를 정식 도구로 교체한다. `dist/`는 생성물이므로 Git에서 제외한다.

Windows 앱은 이 UI·엔진을 Electron 또는 Tauri로 감싸고 저장 어댑터를 파일 시스템으로 바꾸는 방향을 검토한다. 현재 Node 서버나 빌드 스크립트를 앱의 필수 실행 의존성으로 만들지 않는다.

## 후속 기능을 넣을 자리

- 지도 이미지·자유형 경계: `territories`의 위치/형상 모델과 인접 관계 공급자를 확장하고 지도 렌더러를 교체한다. 현재 행/열 이외의 사용자 인접 관계는 저장하지 않는다.
- 초상화·국기: 인물·국가 데이터와 저장 어댑터에 이미지 자산 참조를 추가한다. 지금 외부 이미지 URL을 임의 실행하거나 가져오지 않는다.
- 상세 게임 규칙: 엔진을 생산·보급·전투·인사 등으로 세분화하고 `rules`와 `engineVersion`을 올린다. 기존 세계·실행 파일의 마이그레이션을 먼저 설계한다.
- 관리자 개입: 실행 상태 변경을 별도 사건으로 남기고 상태 검증을 통과시킨다. 현재 편집 세계 변경을 실행에 직접 섞지 않는다.
- 재생·분기: 기록 적용기와 체크포인트를 더한다. 시작 세계+시드로 재실행할 때 엔진 버전도 고정한다.
- 녹화용 연출·자막: 엔진 사건을 읽는 표현 계층과 표시 설정을 확장한다. 연출용 난수·시간은 게임 판정에 영향을 주지 않아야 한다.

## 변경할 때

UI 수정은 관련 화면과 좁은 너비를, 규칙 변경은 엔진 테스트와 기록을, 데이터/저장 변경은 기존 파일 왕복과 잘못된 입력 거부를 확인한다. `npm test`, `npm run check`, 영향이 있는 브라우저 시나리오를 실행한 뒤 문서와 Git 버전을 갱신한다.
