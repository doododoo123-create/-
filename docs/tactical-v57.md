# v0.57.0 집단군 전술창

기준은 v0.56.0, 원본 SHA-256 `56ca58708e505328ce85bb4263860d4fb2b5a33142809b4489cc1c566e90af1f`다. 사용자 과업지시서는 [원문](reference/v57/mass-battle-spec.ko.md)에 보존했다. 원본 실행 파일은 Git 태그 v0.56.0에 보존되어 있다.

## 적용 범위

전술창은 이미 정해진 전투 기록을 읽는 재생기다. 새로운 전술 효과, 주사위, 피해, 포위 보정, 이동 거리, 피로, 보급이나 점령 규칙을 만들지 않는다. 동일 기록의 승패·손실·전사·최종 소유권을 유지한다.

사용자가 별도로 승인한 진입 변경만 예외로 포함한다. 집단군은 전장 도착까지 유지되고, 실제 전투 아이콘 양옆에 집단군/개인 대표가 선 다음 아이콘에서 전술창이 펼쳐진다. 끝난 뒤에는 기존 지도 recap에서 개별 부대로 표시한다. 그 밖의 지도 카메라·줌·후퇴·빗금 공개 순서는 변경하지 않았다.

## 읽을 수 있는 연속 전개

- 같은 장수가 이어 싸우는 순서를 지킨다. 원래 교전 하나마다 실제 승리·패배·무승부 또는 무전투 진입을 표시한다.
- 독립 부대의 접근은 겹쳐 보여줄 수 있지만 결과는 읽는 시간에 맞춰 순서대로 공개한다. 전장은 매 교전마다 초기화하지 않는다.
- 상단에는 현재 지역·교전 결과와 해당 지역들의 소유국 표시줄을 둔다. 부대 이름·병력은 지휘관마다 하나의 장부로 관리한다.
- 영토 장부는 중간 프레임의 소유권 변화를 읽는다. 점령 후 재탈환도 별개 사건으로 표시한다. 종료의 획득/상실은 기존 **순변화**이고, 과정의 점령/반격 점령/재탈환 횟수는 별도다.
- 실제 손실은 각 교전의 만 명 또는 한 명 단위로 분할한다. 공격 이미지의 타격 프레임에서 실제 상대와 접촉할 때 차감한다. 손실 0에는 피해를 만들지 않고, 1단위 손실은 한 번만 공개한다.
- 증원·재편·전사 시 병력 이송은 전투 피해와 분리한다. 분류할 수 없는 차이는 ‘기록상 병력 정리’로 명시하고 진단에 남긴다. 마지막에 몰래 병력을 맞추지 않는다.
- 병력 0과 전사를 구별한다. 실제 전사 사건만 사망으로 처리하며, 전사 이후 이동·공격을 멈춘다.

## 병력 규모와 접촉

양국 공통 축척을 사용하며 큰 쪽 기준 최대 480명, 합계 최대 960명의 병사 그림을 배정한다. 예를 들어 5만:30만은 80:480, 60만:1만은 480:8이다. 지휘관 수가 많다고 각자 최소 8명씩 추가하지 않는다. 정수 그림 배정 오차는 진단에 기록한다.

큰 부대는 여러 시각 구획으로 나누지만 실제 지휘관·병력·전적은 하나다. 각 구획의 가중치 합은 1이며 표시용 분할이 병력 복제가 되지 않는다. 작은 부대에 닿는 접촉 자리는 최대 3개로 제한하고 대열을 교대한다. 대기 중인 구획은 공격하거나 피해를 만들지 않는다.

60만 단일 장수 등 극단 사례는 **표시 계층 시험 자료**다. 실제 게임의 장군 최대 지휘한도 25만을 바꾸지 않는다. 기존 병사의 측면/사선 이미지와 좌우 반전을 재사용하므로 새 정면·후면 원화가 추가된 것은 아니다.

## 전술별 움직임

| 전술 | 이동과 상대 반응 | 적용 조건 |
| --- | --- | --- |
| 중앙 집중 돌파 | 좁은 쐐기로 접근, 실제 승리 후 전개 | 기록상 공격 승리 |
| 편익 집중 | 한쪽 **정면**에 집중, 적 전열 이동 | 공격 구획 2개 이상 |
| 사선 진격 | 날개→중앙→반대편의 시차 진입 | 공격 구획 3개 이상 |
| 양익 협공 | 중앙 고정, 양 외곽 우회, 적 양끝 회전 | 공격 3·수비 2구획 이상 |
| 편익 포위 | 한쪽 외곽만 크게 돌아 측면 접촉 | 공격 2구획 이상 |
| 돌출부 확대 | 앞서 열린 돌파구 통과 후 전개 | 같은 공세의 앞선 실제 점령/돌파 |
| 파상 공세 | 앞 대열이 빠지고 다음 대열이 같은 접촉면을 교대 | 공격 구획 2개 이상 |
| 집중 압박 | 같은 전면에서 짧은 반복 전진 | 실제 유인 전투 |
| 후속대 투입 | 후방 대기 뒤 접촉 전선으로 투입 | 공격 구획 3개 이상 |
| 전선 유지 | 짧게 양보하고 기준선으로 복귀 | 실제 유인 전투 |
| 국지 역습 | 방어 후 가까운 기준선까지만 되밀기 | 실제 방어 승리·역점령 없음 |
| 반격 돌파 | 주도권 교체 후 기준선 너머 진격 | 실제 역공/방어 승리와 점령 |
| 단계적 후퇴 | 엄호·후퇴 구획을 교대로 움직임 | 패전 측 복수 구획 |
| 분리된 철수 | 서로 다른 퇴로로 나뉘어 이동 | 패전 측 복수 구획 |

조건에 맞지 않으면 가능한 방식으로 전환하고 그 이유를 계획의 `fallback`에 남긴다. 소규모 전투는 복잡한 우회를 줄인다. 검증용 강제 선택도 실제 서비스와 같은 경로 생성기를 호출한다.

## 시간과 조작

교전 수·인과관계에 따라 길이가 달라진다. 일반 4대4 검증 기록은 약 43초, 복잡한 15개 교전 기록은 약 81초다. 실제 기록이 단순하면 16초 이상에서 종료한다. 시간을 채우기 위한 가짜 전투나 재탈환은 만들지 않는다. 많은 교전은 접근·공격의 간격을 줄이되 결과 읽기 시간은 남긴다.

기존 배속·정지·다시 보기·건너뛰기·상세 기록·지도 복귀를 유지한다. 중요 사건의 1배속 처리와 종료 요약 1초 정책도 그대로다. 한 개 Canvas와 기존 지도 RAF를 사용하며 병사별 DOM·타이머·경로탐색은 만들지 않는다. 화면 DPR은 최대 2로 제한한다.

## 코드

- `tactical-record.js`: 실제 기록·정수 손실·증감·전사·소유권 장부와 엄격한 검증.
- `tactical-scale.js`: 공통 병력 축척·정수 배정·표시 구획.
- `tactical-maneuvers.js`: 전술 조건과 실제 경로·대응.
- `tactical-story.js`: 연속 교전·접촉 자리·타격·결과 공개 시간표.
- `tactical-sample.js`: 임의 재생 시점의 순수 상태 계산.
- `mass-battle-animation.js`, `mass-battle-view.js`: 기존 Canvas와 이름표·현재 교전 UI.
- `battle-entry.js`, `army-presentation.js`: 승인한 집단군 유지 진입.

실행: `npm start`. 테스트: `npm test`, `npm run check`. 단일 HTML 갱신: `npm run release`. 외부 API·유료 서비스·CDN 없이 실행한다. 모바일 별도 버전은 만들지 않는다.
